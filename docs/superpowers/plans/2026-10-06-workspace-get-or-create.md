# 工作空间申请直接返回可用沙盒

用户再次明确：同一个 workspace 申请应直接获得已有可用环境，正常争用和恢复由服务端处理。

- 创建 HTTP 入口使用 Manager.GetOrCreate；无 workspace 的请求保留原创建语义。
- 按完整工作空间存储身份串行化申请，本地 context-aware 锁和现有可续期 Redis CAS 锁协调多副本。锁争用在服务端等待。
- 已有可用实例返回相同 ID，不改变其配置或 TTL，不创建候选 runtime。
- 发布/挂载/独占操作和快照竞争在请求期限内重查；恢复租约及 lifecycle，再验证可用性。
- 过期或已进入销毁的权威生命周期走正常清理流程后重新申请，不因争用销毁健康实例。
- 没有归属、租约或历史候选才创建。缺失权威元数据的旧 owner 不可盲目删除，返回明确恢复故障并在服务端记录原因。
- 验收：重复申请、并发跨副本、真实 Redis、FUSE、local bind、租约过期恢复后执行命令、配置保留、临时状态内部等待、取消、依赖故障不创建替代实例；HTTP/SDK 直接申请结果一致。
