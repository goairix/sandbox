# Helm Chart 0.3.0 与 Sentinel 升级整洁性实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 发布独立 Helm Chart `0.3.0`，让已初始化 Sentinel 在无关升级中不再重复创建身份/初始化 Job，并提供 API-only 升级和 45 秒 FUSE refill lease 接管的可重复验收工具。

**Architecture:** Helm helper 通过实时 `lookup` 生成不可伪造的 Sentinel `identityExists`/`phase` 状态，两个普通 Job 仅在确有工作时渲染。升级验收采用本地只读快照比较；FUSE lease 验收使用显式 opt-in 的 Go 集成测试，连接测试 release 的 API 与 Redis，并依赖锁 TTL 自动恢复。

**Tech Stack:** Helm 3、Go 1.25、Kubernetes 1.33+、Bash、kubectl、jq、Redis Sentinel。

---

```go
func renderSentinelState(t *testing.T, phase string, identity bool) ([]map[string]any, []byte) {
    t.Helper()
    chart := copyChart(t)
    members := []string{
        "sandbox-redis-sentinel-0.sandbox-redis-sentinel-headless.release-ns.svc.cluster.local",
        "sandbox-redis-sentinel-1.sandbox-redis-sentinel-headless.release-ns.svc.cluster.local",
        "sandbox-redis-sentinel-2.sandbox-redis-sentinel-headless.release-ns.svc.cluster.local",
    }
    cluster, err := json.Marshal(map[string]any{"clusterID": "fixture-cluster", "members": members, "phase": phase})
    require.NoError(t, err)
    cm, err := json.Marshal(map[string]any{"data": map[string]string{"cluster.json": string(cluster)}})
    require.NoError(t, err)
    replaceLookup(t, chart,
        `lookup "v1" "ConfigMap" .Release.Namespace (printf "%s-state" $name)`,
        `(fromJson `+strconv.Quote(string(cm))+`)`)
    if identity {
        replaceLookup(t, chart,
            `lookup "v1" "Secret" .Release.Namespace (include "sandbox.sentinelIdentitySecretName" .)`,
            `(fromJson `+strconv.Quote(`{"metadata":{"name":"sandbox-redis-sentinel-identity"}}`)+`)`)
    }
    return renderChartResult(t, chart, autoSentinelOverrides()...)
}
```

`copyChart`、`replaceLookup` 和 `renderChartResult` 都只操作测试临时目录；生产 Chart

脚本使用 `set -euo pipefail`，接受显式 context/namespace/release；允许测试用
`KUBECTL_BIN` 覆盖命令，生产默认 `kubectl`。采集函数生成规范 JSON：

```bash
collect() {
  deployment="$($kubectl --context "$context" -n "$namespace" get deployment "${release}-api" -o json)"
  statefulset="$($kubectl --context "$context" -n "$namespace" get statefulset "${release}-redis-sentinel" -o json)"
  pods="$($kubectl --context "$context" -n "$namespace" get pods -l "app=sandbox-redis-sentinel,release=$release" -o json)"
  jobs="$($kubectl --context "$context" -n "$namespace" get jobs -l "release=$release" -o json)"
  jq -n --arg context "$context" --arg namespace "$namespace" --arg release "$release" \
    --argjson deployment "$deployment" --argjson statefulset "$statefulset" \
    --argjson pods "$pods" --argjson jobs "$jobs" '{context:$context,namespace:$namespace,release:$release,
      api:{image:$deployment.spec.template.spec.containers[]|select(.name=="sandbox")|.image,
           generation:$deployment.metadata.generation,observed:$deployment.status.observedGeneration,
           replicas:$deployment.status.replicas,ready:$deployment.status.readyReplicas,
           updated:$deployment.status.updatedReplicas,available:$deployment.status.availableReplicas},
      redis:{currentRevision:$statefulset.status.currentRevision,updateRevision:$statefulset.status.updateRevision,
             replicas:$statefulset.status.replicas,ready:$statefulset.status.readyReplicas,
             template:($statefulset.spec.template|tojson|@base64),
             pods:[$pods.items[]|{name:.metadata.name,uid:.metadata.uid,
               restarts:([.status.containerStatuses[]?.restartCount]|add//0),
               imageIDs:[.status.containerStatuses[]?.imageID]|sort,ready:any(.status.conditions[]?;.type=="Ready" and .status=="True")} ]|sort_by(.name)},
      jobs:[$jobs.items[]|select(.metadata.name|test("-redis-sentinel-(identity|initialize)-"))|.metadata.name]|sort}'
}
```

`verify` 先重新 collect，再用 jq 检查：身份参数一致、API image 改变且 rollout 完成、Redis
revision/template/Pod UID/restarts/imageID 完全相同、3/3 Ready、Job 集合没有新增。每个失败
条件打印具体字段，并返回非零。快照写入采用临时文件后原子 `mv`，权限设为 `0600`。

```go
func loadConfig(t *testing.T) config {
    t.Helper()
    if os.Getenv("SANDBOX_REFILL_LEASE_TEST") != "1" {
        t.Skip("opt-in deployed FUSE refill lease test")
    }
    cfg := config{APIURL: os.Getenv("SANDBOX_REFILL_TEST_API_URL"), APIKey: os.Getenv("SANDBOX_REFILL_TEST_API_KEY"), PoolKey: os.Getenv("SANDBOX_REFILL_TEST_POOL_KEY"), RedisAddr: os.Getenv("SANDBOX_REFILL_TEST_REDIS_ADDR"), RedisPassword: os.Getenv("SANDBOX_REFILL_TEST_REDIS_PASSWORD")}

    require.NotEmpty(t, cfg.PoolKey)
    require.NotEmpty(t, cfg.RedisAddr)
    cfg.ExpectedCapacity = 3
    return cfg
}
```

API 使用测试 release 的 Service/port-forward。凭据仅从环境读取，不打印。

- [ ] **Step 2: 写接管行为测试**

测试流程固定为：

```go
before, err := repo.ListByPoolKey(ctx, cfg.PoolKey)
require.NoError(t, err)
require.Equal(t, cfg.ExpectedCapacity, countPrepared(before))

oldToken := "acceptance-old-" + uuid.NewString()
var lockErr error
var locked bool
require.Eventually(t, func() bool {
    locked, lockErr = repo.TryRefillLock(ctx, cfg.PoolKey, oldToken, 45*time.Second)
    return lockErr == nil && locked
}, 20*time.Second, time.Second, "a stable full pool never released its transient refill owner; abort without changing the pool")
lockedAt := time.Now()

sandboxID := createFUSESandbox(t, client, cfg)
require.Less(t, preparedCount(ctx, repo, cfg.PoolKey), cfg.ExpectedCapacity)
for time.Now().Before(lockedAt.Add(40 * time.Second)) {
    require.Less(t, preparedCount(ctx, repo, cfg.PoolKey), cfg.ExpectedCapacity)
    time.Sleep(time.Second)
}
require.Eventually(t, func() bool { return preparedCount(ctx, repo, cfg.PoolKey) == cfg.ExpectedCapacity }, time.Until(lockedAt.Add(90*time.Second)), time.Second)

renewed, err := repo.RenewRefillLock(ctx, cfg.PoolKey, oldToken, 45*time.Second)
require.NoError(t, err)
require.False(t, renewed)
destroySandbox(t, client, cfg, sandboxID)
```

`t.Cleanup` 只销毁本测试创建且仍存在的 sandbox；不删除 refill lock、pool record、PVC、
Secret 或 Sentinel state。测试异常时让旧锁自然过期。
