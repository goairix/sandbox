# Resident due worker and recoverable discovery

This continues the approved `2026-10-06-etcd-state-management-design.md` partition scheduling design. The due-discovery Task supplies atomic v3 candidates, original-worker fixed-revision pages and fenced metadata expiry admission. This design consumes those APIs in a real owned worker loop; it does not replace the later physical task executor or reopen accepted Tasks.

## Outcome

An explicitly started worker owns a bounded set of original partition/session and shared budget capabilities, continuously discovers near-term expiry and calls the real `AdmitExpiredTask`. It coordinates explicit renewal, persistent scan progress, fixed-revision list-to-Watch continuity, bounded candidate storage and truthful synchronization/lag status. Cancellation and Backend.Close physically join its actual work before resources can be replaced. Default Redis startup is unchanged until the remaining business and physical execution paths are ready.

The intended benefit for many existing sandboxes is to process bounded nearby changes and retained backlog without keeping every idle sandbox in memory, creating per-sandbox controllers or repeatedly restarting a successful long scan. This is an implementation objective, not measured performance or capacity acceptance.

## Binding constraints

- Keep 256 logical partitions, the existing original worker profile and cell-wide fixed budgets: at most four relists, 20 MiB/s Range shares and 100 claim attempts/s. Actual task hard concurrency 32 remains a separate persistent execution protocol; admitting metadata tasks does not consume or prove those physical slots.
- Each worker explicitly owns one relist share and configured distinct lists of Range and claim shares, rather than being limited to one 1/s claim share. Configure 1..20 Range IDs and 1..100 claim IDs from the existing finite pools, copy/validate inputs and acquire only those exact IDs. Select ready original claim shares fairly; each page cursor remains pinned to its original Range share. This permits a few sessions to use the existing cell budget without increasing it or claiming measured throughput.
- Original sessions own authority; references, candidates, watch events, cache entries and persistent progress are diagnostic only. Every actual expiry metadata commit continues through the existing original-worker/profile/partition/claim-share and current-control fences. Do not weaken or rebuild original capabilities, generic Stage semantics, 64-node native limits or 256 KiB wire ceilings.
- The loop must execute actual discovery and expiry admission, not add an unused controller interface. Coordinate session renewal between finite original native operations; no goroutine, Lease, Watch or permanent cache entry per sandbox. Keep goroutine and native owner counts bounded by worker/session/partition configuration. Fresh replacement sessions reconstruct only validated discovery state, never an old opaque cursor or original authority.
- Persist exact revision/window/list phase and scan frontier under current original worker/partition fences. Advance only after the covered candidates have known settled metadata outcomes or fresh authoritative rejection; retain original attempt identity and halt covered advancement on unknown results. Checkpoint writes use exact CAS and complete response/byte/node preflight; they grant no physical cleanup permission.
- A fixed-R scan followed by Watch at R+1 must include inserts below its listing frontier. Do not resume at a newer page header revision or acknowledge memory-only unprocessed future candidates durably. Compaction of R invalidates that view; bounded relist is required. Moving the next-60s window must use another explicit fixed-revision list/Watch bridge, including future entries that become due without another write.
- Each Range remains at most 118 records and 256 KiB, charged before dispatch through the actual original share. The worker candidate/cache budget is at most 64 MiB and 10,000 keys, accounting owned keys, values and queue/heap/map overhead conservatively. Merge by exact entity/key without an all-far-future heap. Overflow, malformed stream, unfinished fragment or unprovable continuity stops cache-driven admission and discards invalid discovery state for bounded resynchronization; permanent due/task evidence remains.
- Use a shared native Watch stream for bounded partition subscriptions, never sandbox subscriptions. Bound memory before native response allocation as well as after decoding; a bounded application channel on top of clientv3's unbounded watch buffer is insufficient. Preflight must choose an exact supported transport over the original authenticated connection, receive/fragment/event bounds, progress/revision validation and finite cancellation/join. Watch data never supplies authorization. No second client, token or authentication bypass merely to get an unbounded stream working.
- The selected stream uses the original authenticated connection, call-scoped validating proto codec, at most 118 events/256 KiB per complete assembly, and aggregate predecode limits of 512 frames/10,000 events/8 MiB per turn. Deduplicated guards preserve every original participant in groups of at most 56 comparisons plus one identity read and four failure reads (61 nodes). The turn context is clipped to min(3 seconds, configured session TTL/3, remaining original deadline); its stream occupies at most 500 ms and half the remaining time. Deadline expiry never substitutes for physical Send/Recv joins.
- A completed list and actual Watch replay must cover the native pre-guard revision barrier before claiming synchronized history. Post-guards independently verify current original authority; later unrelated writes may make their observed revision exceed covered revision and must be shown as a replay tail rather than erase already proven history. Created headers never prove replay or establish monotonic historical data headers. Progress requested before all subscriptions catch up may yield no reply, so bounded retries follow receipt of every Created ACK.
- Known idle stream timeout and local bucket exhaustion are scheduling conditions, not permission to recreate a healthy original session or silently retry an unknown metadata mutation. Original fence loss, identity loss, malformed authority and original deadline remain conservative terminal conditions. Backoff waits must be context-cancelable and coordinate renewal; no tight polling on empty budgets.
- Readiness/status reports synchronized partition coverage, list/watch phase, invalidation, backlog/lag and unknown attempts truthfully. A partial or over-budget rebuild is not healthy coverage. No N runtime GET or restoration of old per-sandbox loops on takeover. Server-side Range Count/backlog CPU remains a capacity measurement concern; small payload is not a constant-CPU guarantee.
- All edits use apply_patch. Root alone executes Go/Git/Docker/gofmt and commits verified coherent slices. No unrelated Sentinel document, closed OWN/pairs/artifacts, duplicate implementation author or old native matrix replay.

## Scope and acceptance

The read-only preflight must freeze exact controller/checkpoint/Watch APIs, file boundaries, node/byte bounds and original lifetime integration before tests or product edits. If a concrete safe combined protocol cannot fit, identify the exact conflict and settle it before implementation, rather than adding a partial carrier and claiming a running worker.

Focused tests must drive the real loop against actual client/gRPC boundaries: expiry produces one permanent task; fixed-R late insertion below the frontier is not missed; restart resumes safe progress with new original authority; unknown admission retains its exact attempt and does not advance/retry; early candidates survive timer/window rollover; compaction/fragment/gap/overflow invalidate and resynchronize; renewal and budget backoff make progress without session churn; cancellation/partition release/Backend.Close join real work. Root runs genuine RED, host/race and Linux vet for coherent slices and commits each passing slice promptly. One new finite three-member native test covers actual resident-loop expiry, late insertion/restart and original-fence failure/cleanup. One fresh sole author and one whole-Task reviewer provide scoped acceptance.

Physical pending-task discovery, persistent 32 task slots, runtime drain/archive/termination driver, deployment worker configuration, manual stale-index GC, historical index coverage, FUSE/collector, large-N/fixed-change-rate capacity, production cutover and Redis removal remain subsequent work. This Task must expose those limits explicitly.
