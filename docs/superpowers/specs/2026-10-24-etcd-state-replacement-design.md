# Sandbox 状态存储替换设计

## 目标与基线

从 `feat/workspace-fuse-mount`（`c14a52c`）出发，让新部署的 sandbox 使用 etcd 管理原 Redis 承担的分布式状态。HTTP、FUSE、运行时和业务结果以基线行为为准。新环境没有旧 Redis 状态和旧沙盒；不实施数据迁移或接管。当前 `codex/etcd-state-management` 留作只读参考，不整支合并。

验收结果是创建与同 workspace 并发申请、复用、显式和 TTL 销毁、配额归还、跨副本并发及重启恢复均在 etcd 下通过。大量已存在沙盒必须纳入容量验证；不能只测申请吞吐或远期不过期的元数据。

## 基线职责与边界

`cmd/sandbox/main.go` 目前创建一个 Redis Store，并将它交给 session、ephemeral、multipart、workspace、普通池、FUSE 池和活跃沙盒仓库。对应契约在 `internal/storage/state/state.go`、`active_sandbox.go` 和 `pool.go`。普通 `AtomicStore` 可用 etcd 的 compare/put/delete 与 lease 实现；活跃沙盒及 FUSE 池的 Redis Lua 脚本包含多键原子状态转换，须分别映射成有界 etcd 事务，不能用单键 CAS 代替。

保持原业务层和 API 层的行为。新增代码只放在存储适配、必要的有界索引/遍历、配置和接线位置；遇到契约表达不了的安全条件，先提交复现和影响范围，再决定是否扩展接口。不得引入新的运行时协议、凭据体系、清理 actor、退款账本或平行 HTTP 服务。

## 存储语义

- 所有 key 位于一个配置的命名空间前缀，按用途分组；比较使用 etcd revision/lease 和完整身份，不以本地缓存决定所有权。
- `SetNX`、CAS、删除和计数器必须定义 ACK 丢失后的读回或 Unknown 行为。不得因请求超时直接重发可能产生第二次效果的操作。
- TTL 仅用于可过期的申请、锁和操作租约；持久的沙盒、所有权与清理进度不能因为 API 实例退出而自动消失。释放配额须在确认原有终止条件后执行。
- `Keys` 的现有 pattern 调用须逐点清单化。生产遍历按前缀、分页和限流；不做全库扫描，也不为每个沙盒建立独立 watch。无法安全映射的 pattern 是阻塞项。
- 多键事务必须实际核对比较数量、请求大小及冲突成本。etcd 限制不得通过任意抬高集群上限掩盖。每个事务的授权前像和写入结果要能在重启后确定读回。

## 容量与部署

容量模型以**同时存活沙盒数 N**为主变量，分别测 10k、100k 或环境可承载的明确上限：etcd key 数、DB 大小、常态维护 QPS、到期突发 QPS、p95/p99 延迟、后台扫描时长、watch 数和压缩/碎片整理后的可用性。测试包含真实过期分布和集中到期，不以静止元数据子集代替。每个 cell 的负载边界从实测给出，超过边界时先给分 cell 的部署量化方案，不先改业务协议。

新环境仅配置 etcd；在原业务验收完成后移除新部署的 Redis 入口、配置和依赖。旧分支和旧测试环境的数据保留，不作为新版本恢复来源。

## 交付与停损门

第一门是基线职责表和一个最小 `AtomicStore` 真实 etcd 实验。第二门是活跃沙盒、池及工作区多键转换的业务回归。第三门是创建→到期→确认终止→退款与重启恢复的真实环境整链。第四门是大量存活沙盒容量和新部署。

每门输出通过/失败、具体版本、命令和关键指标；失败保留原结论。不按文件数、提交数或组件测试数报百分比。单门超过一个工作日仍无可验证的业务进展，停止扩展，报告阻塞、最小修法与是否仍在原目标内。任何需要改变运行时/FUSE协议的提案先单独说明，不在本方案中顺手实施。
