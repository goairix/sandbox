# Sandbox Files v2 通用文件接口设计

## 目标与边界

为沙盒提供一套面向普通应用和 Agent 的文件接口，减少多次 `exec`、整文件下载和客户端拼接命令。新接口与现有 `/api/v1/sandboxes/:id/files/*`、Go SDK 方法并行；v1 的请求、响应和行为不变。业务迁移完成后另行决定何时移除 v1。

公开接口不引用 Eino 类型，也不要求沙盒服务依赖 Eino。Eino v0.9.22 的 `filesystem.Backend` 六个方法是兼容性验收用例之一，其他 SDK 和业务可以直接使用同一组通用能力。

本设计只涉及运行中沙盒的文件操作。不改变 sandbox 创建、调度、etcd 状态、FUSE 挂载和对象存储布局。不引入常驻文件 sidecar、独立文件元数据库或新的写入队列。

## 分层

```text
业务 / Agent 适配器（可选 Eino Backend）
              ↓
Go SDK Files 客户端 / 直接 HTTP
              ↓
独立的 /api/v2/sandboxes/:id/files 路由与 FileService
              ↓
现有 Runtime 的 Docker / Kubernetes 文件执行通道
              ↓
沙盒内 /workspace 或 /tmp
```

`FileService` 只处理路径授权、输入限额、错误分类和调用编排；具体读写和搜索在沙盒文件系统旁执行。相同操作可以由 Docker 和 Kubernetes Runtime 实现，不把 HTTP、Eino 或对象存储协议下沉到 Runtime。首版沿用现有执行通道；只有测得性能瓶颈时才讨论常驻进程。

## 路径与共同规则

- 所有请求都绑定一个已授权的 sandbox ID。默认根为 `/workspace`；显式绝对路径只允许 `/workspace` 和 `/tmp`，与 v1 的可访问范围一致。适配器将自己的虚拟根映射到 `/workspace`。
- 规范化路径后，在实际打开文件时再次验证边界；符号链接不得逃出允许的根。FUSE 内部保留路径在 stat、list、read、glob、grep 和写操作中统一隐藏或拒绝。
- 返回路径统一为沙盒内绝对路径；列表和搜索按路径、行号稳定排序。取消请求应停止继续扫描和输出。
- 文本方法接收 UTF-8 字符串并保留原有换行字节；二进制方法传输原始字节。字节偏移和行号使用不同字段名，不共用 `offset`。
- 默认列表每页 200 项、最多 1000 项；文本读取响应最多 1 MiB，文本编辑文件最多 8 MiB。流式上传沿用现有 `maxUploadBytes` 配置。glob/grep 单次最多扫描 10000 个文件或 64 MiB 内容、返回 1000 项，服务端最多执行 5 秒；部署可调低这些上限，不可由请求放大。达到上限时 API 明确标记未完成或返回限额错误；适配器不得把部分结果当完整结果。

## 首版接口

所有路径参数通过 query 或 JSON 字段传递，不将任意文件路径拼进 URL 路由。下表中的路径均以 `/api/v2/sandboxes/:id/files` 为前缀。

| 方法与路径 | 语义 | 关键输出或约束 |
| --- | --- | --- |
| `GET /stat?path=` | 查看单个文件或目录 | 路径、类型、大小、修改时间 |
| `GET /list?path=&cursor=&limit=` | 列单层目录 | 同一排序规则的游标和 `next_cursor`；无目录全量计数承诺 |
| `POST /glob` | 递归匹配路径 | `path`、`pattern`、限额、`truncated`；支持 `*`、`**`、`?`、字符类 |
| `POST /grep` | 在沙盒内搜索内容 | 正则、范围、glob、文件类型、大小写、多行及前后文；返回路径、1 起始行号和内容；限额与 `truncated` |
| `GET /content?path=` | 流式读取原始字节 | 支持 HTTP Range；不经 JSON/base64 包装 |
| `PUT /content?path=` | 创建或覆盖原始字节 | 流式请求，支持明确的 `create_parents`；请求体大小受配置约束 |
| `POST /text/read-lines` | 按行读取 UTF-8 文本 | `start_line` 从 1 开始，`line_count=0` 表示读至末尾但仍受结果字节上限约束 |
| `POST /text/edit` | 在服务端精确替换文本 | `old_string` 非空且不同于 `new_string`；非 `replace_all` 时匹配次数必须恰好为 1，否则不写入并返回冲突 |

`grep` 的正则与过滤语义以明确版本的 ripgrep 为准。实现使用固定程序和结构化参数，不经 shell 拼接用户输入；搜索在沙盒侧执行，不逐文件经 HTTP 下载。无法支持的正则或过滤选项返回明确错误，不静默降级。

`text/edit` 在同一次服务端操作中读取、计数和写回；不会声称它对沙盒内其他进程的并发写入具有事务级隔离。客户端需要避免覆盖并发更改时，可先读后传文件指纹作为条件；服务端只有能在实际写入时校验该条件才接受，否则返回不支持，不提供虚假的 CAS 保证。

## 后续通用文件管理接口

首版核心能力验收后，在同一 v2 命名空间增加 `mkdir`、`copy`、`move`、`delete`、按行范围编辑和可恢复分片上传。每种管理操作明确是否递归、是否覆盖和源/目标范围；大文件上传沿用现有大小限制。`move` 在 FUSE/对象存储上可能由复制及删除组成，不承诺跨文件或跨目录原子性。这些能力可分批交付，但在讨论移除 v1 前，必须完成现有文件能力的逐项覆盖或确认对应调用方不再使用。

## 写入完成与 FUSE

`PUT /content` 和 `text/edit` 的成功表示沙盒内本次写入已关闭，后续从同一沙盒读取可看到结果；它不自动表示对象存储已完成远端持久化。需要持久化确认的业务继续调用现有 workspace 同步能力，并以该能力的结果为准。写入、关闭或同步结果不确定时返回明确错误；SDK 不自动重试 `text/edit` 等非幂等操作。

## 错误模型与 SDK

v2 使用稳定错误码：非法输入、路径越界、路径不存在、类型不符、匹配不唯一或条件冲突、限额超出、沙盒未就绪、结果未知。HTTP 状态分别使用 400、403、404、409、413、503 等适当状态，并在响应体保留机器可读的错误码。错误中不包含文件内容或凭据。

Go SDK 提供 `Files.Stat/List/Glob/Grep/Read/Write/ReadLines/Edit`。`Read` 返回需由调用者关闭的 `io.ReadCloser`，`Write` 接收 `io.Reader` 与明确字节数；后续管理方法归在同一 `Files` 客户端。SDK 保留调用者传入的 `context.Context`，对内部消费的响应体负责关闭，并将 v2 错误码映射成可识别的错误类型。v1 SDK 方法保持原样。

## Eino 兼容性验收

独立适配器将 Eino v0.9.22 的 `LsInfo`、`Read`、`GrepRaw`、`GlobInfo`、`Write`、`Edit` 映射到 v2 SDK。`Read.Offset` 是 1 起始行号；`Edit.ReplaceAll=false` 要求唯一匹配；`GrepRaw` 不能把 `truncated=true` 当作完整结果。可选 `Shell` 沿用沙盒执行接口，可选多模态读取单独设计，不进入本首版的文件 API 合同。

适配器的路径映射、错误语义和六方法行为用 Eino v0.9.22 的实际接口编译与契约测试验证；沙盒服务本身不添加 Eino 依赖。

## 验收与迁移

1. v1 路由及现有 SDK 回归保持通过；v2 只新增路由和类型，不重解释 v1 字段。
2. Docker 与 Kubernetes/FUSE 分别覆盖：文本和二进制读写、空文件、Unicode 与 CRLF、行号、唯一和重复匹配、glob/grep、符号链接越界、保留路径、取消和限额。
3. 在真实 FUSE 沙盒验证同沙盒读回与显式 workspace 同步；记录两者不同的完成语义。
4. 业务可逐个调用方切换；通过流量与错误率观察完成迁移。Eino 六方法契约测试只是其中一项适配验收。删除 v1 前再核对旧能力调用清单、v2 覆盖与真实业务回归，并单独决策。

## 方案取舍

直接把 Eino 的六个 Go 方法公开为 HTTP 最省适配代码，但会使通用 API 依赖单一框架且缺少二进制流。只把旧 v1 SDK 包一层最快，却继承整文件下载、缺少 grep 和编辑匹配语义。选用通用 v2 文件能力加薄适配器，可以独立服务普通业务，并以 Eino 作为一项确定的兼容性验收。
