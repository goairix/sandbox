# Original Backend workspace archive delivery

Approved parent: `2026-10-06-etcd-state-management-design.md`, stages one through five. This unit connects accepted original command preparation and bounded private receiving; it does not switch the main application to etcd.

## Contract

Add optional `Options.TaskWorkspaceArchiveSpool *TaskWorkspaceArchiveSpoolOptions`, with `Directory string` and uint64 `Jobs`, `JobBytes`, `TotalBytes`, `Entries`, `JobIndexBytes`, `TotalIndexBytes`. Copy the options. Absent configuration preserves existing Backend construction; delivery refuses without an original store. Reuse the accepted private store's limits, empty/preexisting real-UID0700 directory, exclusive directory lock and conservative cleanup. Constructor validation has no filesystem/callback effects; actual opening follows native namespace verification. Failure closes acquired resources. No cold file scan, deletion or quota reset.

Add `Backend.ReceiveTaskWorkspaceArchive(ctx context.Context, prepared *PreparedTaskWorkspaceArchive) (*ReceivedTaskWorkspaceArchive,error)`. The returned type is instance sealed to the original Backend, claim, prepared command and private spool/witness. Its only public operation is `Close() error`, an idempotent physical cleanup join. It exposes no path, FD, ticket, guard, provider or release capability. Future provider consumption must freshly check the original current native authority again; this unit cannot promote signed completion alone into provider settlement.

Only a known successful original command and its exact originally issued Prepared may start delivery. Zero/copied/foreign/cold inputs, ambiguous first native Put recovery, replaced draft, dead claim, expired original preparation/ticket window, absent store and prior attempted delivery refuse. Reserve the complete per-job disk/index/concurrency budget before any command bytes. Seal one original delivery attempt before transport IO; failure or cancellation never resends through this handle. No delivery capability is reconstructed from command history.

Quota rejection before any transport attempt does not consume the send attempt: the same still-live original Prepared may retry admission within its unchanged original window. No new handle or extended deadline is created. Once original transport starts, one-shot refusal remains permanent for that original. Retry-prevention state belongs to the original claim/prepared lifetime; Backend must not retain an unbounded history map of all seen commands. Its retained spools/owners are bounded by configured admission and physically retired originals.

The existing private receiver owns Destination.Open, Send, read and physical Session.Close. Add optional private guards before Open and after authenticated handshake immediately before Send. Both freshly check original claim/guard/base identity/restore epoch, exact original quiescence/receipt/reservation/final-sync/issuer/command revisions and whole operations-prefix emptiness via bounded linearizable native transactions. Do not reuse preparation's old empty revision. Account both branches/replies under existing64 literal nodes,64KiB record and256KiB mutation caps. Use original immutable MOD pins validated during preparation; native delete/recreate changes MOD even for identical bytes. Recheck original admission deadline and trusted short ticket window after any finite guard/clock/handshake delay. Any pre-send refusal emits zero application command bytes.

After original Send succeeds, long body receiving uses the fixed original SessionNotAfter and current live claim, not the expired short preparation/start window. The fixed session window never extends with renewal. Do not reverify the short ticket start window during body receipt. Existing receipt signature/hash/byte count/TAR/actual authenticated EOF/spool identity checks remain mandatory.

## Active ownership and shutdown

No claim mutex is held across transport, body IO, physical Close or owner joins. Native monitoring snapshots immutable comparisons and local state under the claim mutex, performs bounded native IO outside it, then rechecks the original owner. `RenewTaskClaim` must remain usable during a blocked read and can extend only the current claim deadline after its existing native checks; it must notify the active owner of that successfully published deadline without reviving preparation or extending SessionNotAfter. No implicit renewal on behalf of the caller.

Allocate an owner/timers/monitor only after bounded admission. It observes caller context, original claim parent context, fixed session deadline and the latest successfully renewed local claim deadline. At most one bounded native liveness/emptiness check is in flight per active owner; schedule no faster than once per250ms. Native errors/unknown outcomes, changed pins, newly present operations or observed local loss cancel the owner and prohibit a result. Cancellation is followed by physical Session.Close/receiver return/monitor join; uncertainty is an error, never proof of release. Existing direct c.lost assignments are not all notification sites: use bounded active-only observation as the backstop and do not claim universal immediate notification. Local expiry uses the latest published deadline and cannot wait behind a mutex held across native IO; publishing/wakeup design is author's choice provided renewal/expiry tests prove it. Renewal failures and Release explicitly cancel the active owner; joins occur outside c.mu. Release cannot report completion while that original sender is physically active. Native Lease revocation is still metadata cleanup, not safe runtime/provider release.

`Backend.Close` seals new delivery admission, cancels all active spools before joining any, waits for receivers/monitors/cleanup outside claim/store mutexes, and only then closes the native client. Concurrent Close callers share the same result and physical join. Never return an artifact on a failed/canceled Close. Successful artifacts retain quota until original Close; cleanup uncertainty retains files/accounting. Backend close must also retire previously returned artifacts. Optional unconfigured Backends remain valid.

After receiving, perform a fresh original native current-fence and full-prefix empty check plus local/session/caller checks before returning the sealed result. Closing the connection or verifying a receipt is insufficient. Concurrent Release/Backend.Close/cancellation must suppress or invalidate the original result. Future consumption will need its own fresh guards.

## Evidence and limits

New host and genuine native-etcd + pinned mTLS tests must prove zero bytes for pre-send failures, immutable one attempt, success with real framed bytes/signature/TAR/EOF, lease renewal through a blocked receive and beyond its old deadline, expiry/release/restore/command ABA/operations after Send, post-receive refusal, concurrent physical shutdown and quota retention. Reuse accepted fixture definitions without executing their old selectors. The TLS producer fixture is not an actual PID1 integration test; no production/capacity claim from it. Preserve genuine compiled behavior RED and final new-selector race/vet/Linuxarm64 compile evidence. Source/test/report/format edits use apply_patch; small exact-path commit under this plan's OWN git-commit.lock.

Current command API requires the same actual still-valid query/archive issuer certificate. Keep that bounded constraint; coordinated idle certificate/query/TLS maintenance remains mandatory later. Signed completion, cancellation, lease expiry, mode flags and exit codes do not alone permit safe release.

## Carry-forward provider work

Legacy ScopedFS writers buffer whole files and return untyped Close/Remove errors. The later provider unit must stream bounded native SDK entry readers, admit each actual retry/redirect/multipart wire request under durable original intent/current fencing, and require real response/body EOF plus typed native settlement. OBS MaxRetryCount0 still permits redirects; generic HTTP200 is insufficient for S3 multipart completion. Private HTTP1-only non-reused transport and explicit routing require actual wire tests, not wrapper-count assumptions. No global HTTP hooks, dependency changes, cloud effects or credentials output in this unit.
