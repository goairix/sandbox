# Specification — task-authenticated user quiescence and dual drain

Binding Root-selected contract after documented preflight corrections below. Implementation is dispatched only by an exact task brief; no production cutover authority. Predecessor: current task-data-gate-closure unit, subject to its whole-range acceptance. Master: `docs/superpowers/specs/2026-10-06-etcd-state-management-design.md`, Operation gate, destroy/cleanup and workspace/remote fencing. This draft incorporates Root's selected directions and the current OWN `next-cleanup-decomposition-notes.md`; it does not broaden the existing CloseData receipt.

## 1. Outcome, exclusions and selected decisions

Implement one-way durable USERS admission closure, finite stop/join of all previously registered user executions, fresh whole-PID-namespace proof, and an original-live-claim-fenced linearizable empty operations observation. Successful local evidence concerns one exact Runtime ID/UID/Boot, namespace/authority/restore binding, generation/data-gate epoch and immutable cleanup task birth.

Management TLS, journal/key and diagnostic queries remain alive. `Supervisor.Close()` continues to mean process/transport shutdown; user quiescence is a different operation. Final sync/flush, FUSE/cache drain, runtime termination, remote PUT/DELETE/CompleteMultipart settlement, successful business End, network/mount cleanup, owner/index/control deletion, GC and production cutover are excluded. No boolean or receipt name may suggest these excluded outcomes. Plain mode still needs explicit future no-remote-effect evidence; missing records are not evidence of absence.

Root-selected constraints:

- One immutable quiescence attempt per task. No supersession/replacement of an unknown or aborted attempt, even by a higher task epoch. A new claimant may query history but cannot adopt an old Prepared or resend an effect.
- A historical CloseData receipt can belong to an earlier claimant. A current claimant derives the same exact immutable TaskRecord/destroying birth/runtime/generation/data-gate/restore tuple, while retaining its own current ClaimID/WorkerID/CreateRevision/Lease. Historical proof does not transfer the earlier claim capability.
- Initially eligible target topology is PID1 plus its registered trusted monitors and their user descendants only. Trusted mounter must be outside that PID namespace. No arbitrary UID exemptions or unregistered management child. Unknown process/child, incompatible kernel or incomplete scan means unknown.
- The existing16-connection/5-second request cap remains. A finite lifetime-owned coordinator survives its request connection. An accepted ACK is not a quiescence result. Ticket expiry does not abandon already-owned irreversible stop/join or reopen users.
- Page size16, total copied page80KiB, private cursor; current linearizable pages plus a NEW full-prefix limit1 empty transaction under original complete fences. No revocation/deletion of discovered tokens, no reconstructed OperationCapability, no End.
- Actual combined three-member metadata→protected production PID1→dual drain evidence is mandatory. Separate passing component gates do not substitute for it.

## 2. Authority and public interface proposal

Names and limits below are explicit draft values. Root approval is required before implementation. Existing4096-byte CloseData ticket,8192-byte CloseData receipt,16384-byte etcd CloseData record and all old canonical formats stay unchanged.

Use `TaskUserQuiescenceContext` with explicit snake_case JSON:

- `Current TaskCloseDataContext`: copied complete current command/task/claim binding, using the existing field validations but no purpose conflation.
- `CloseDataContext TaskCloseDataContext`: exact original historical CloseData context, including its original command and claimant.
- `CloseDataTicketDigest`, `CloseDataReceiptDigest` lowercase SHA256; `CloseDataIntentRevision int64 >0`.

Require all permanent task/binding/runtime/generation/data-gate/destroying-birth fields of Current and CloseDataContext equal, including TaskDigest. Their command/issuer/claim/worker/Lease fields need not equal. Current ClaimCreateRevision remains greater than destroying birth. Never compare UUID order. Current claim revision must be >= original CloseData claim revision; if equal, ClaimID/WorkerID/LeaseID are identical. Same exact claim is allowed. The target cannot infer live etcd state from either certificate.

New typed `TaskUserQuiescenceTicketClaims{Version uint32; Purpose string; Context TaskUserQuiescenceContext; NotBefore,NotAfter time.Time}`: version1, purpose `task_quiesce_users`, domain `sandbox-task-quiesce-users-ticket:v1\x00` with actual NUL, limit8192bytes, positive interval<=30seconds and existing conservative current-time checks. Signer matches the Current issuer certificate, key, roots/binding and interval. Runtime checks both its current installed identity and authenticated original terminal CloseData proof. Business ExpiresAt is not a ticket field or cleanup cutoff.

New receipt types are purpose-separated:

- `TaskUserQuiescenceAcceptedClaims{Version; State; Context; TicketDigest; NotBefore; NotAfter}`: state `quiescence_accepted`, domain `sandbox-task-quiesce-users-accepted:v1\x00`, limit12288bytes. It proves durable pending attribution, USERS closure and registration of the single finite owner only.
- `TaskUserQuiescenceReceiptClaims{Version; State; Context; TicketDigest; NotBefore; NotAfter; ExecutionSetDigest string; RegisteredCount,NeverSpawnedCount,LocalTerminalCount uint32}`: state `users_quiesced`, distinct domain `sandbox-task-users-quiesced-receipt:v1\x00`, limit12288bytes. Counts sum exactly, all<=64. State entails complete local namespace proof under the fixed topology; no caller-supplied `drained=true` or remote flag. Exact canonical execution-set digest format is a Task1 prerequisite: ordered by original command UUID, each entry binds original exec context/digest plus either never_spawned or attributed local terminal receipt digest. Empty set has defined SHA256 of canonical empty list, not empty string. Digest is a bounded summary, not a replacement for the producer's owned complete set.

Public protocol functions follow existing typed Sign/Verify/getter conventions, for example `SignTaskUserQuiescenceTicket`, `VerifyTaskUserQuiescenceTicket`, `VerifyTaskUserQuiescenceAccepted`, `VerifyTaskUserQuiescenceReceipt`; no generic signing callback. Verifiers take exact expected context/digest/original interval, freshly validate the pinned exact runtime certificate, return zero evidence on every error, own all bytes and reject duplicate/unknown/missing/null/noncanonical fields. Terminal evidence can be queried after ticket expiry with a currently valid exact runtime certificate. Accepted evidence never grants continued execution or a later phase.

Prepare and dual-drain composition internally query and independently verify prerequisite receipts under backend roots/current certificate and before/after current-claim checks. Caller-supplied bare receipts or booleans do not authorize preparation. PreparedTaskUserQuiescence is opaque original effect-send authority; PreparedTaskQuiescence is a distinct fresh current-claim-bound local next-phase prerequisite, never send authority. Results retain fixed diagnostic Reference/Outcome/optional Prepared/separate GuardCleanupError. Diagnostic query/history cannot reconstruct authority. ## 3. Durable target USERS barrier and execution ownership

Add fixed versioned `users-quiesce.json` and `.users-quiesce.<UUID>.tmp`, with states pending/users_quiesced and explicit full original context, ticket digest/window, fixed result digest/counts only for terminal. Proposed record limit16384bytes. Preflight exact encoded peak pending/barrier/terminal replacement bytes and at most2 additional content temporary files under unchanged256MiB default/70% warning/85% dangerous-work refusal/65536-file hard cap. USERS barrier must be distinct durable state with a reviewed recovery encoding; do not quietly repurpose old gate JSON. Validated pending users-quiesce record itself is the durable USERS barrier; no separate users-gate.json. Every recognized pending/terminal/temp record requires closed diagnostic recovery; cold/poison/absence cannot reconstruct coordinator or reopen users. Strict root scanner and peak accounting are Task1 requirements.

Under the Supervisor admission mutex, validate fresh task command and same installed CloseData proof, close all user Start/Renew paths, fix the complete current execution registration set and register exactly one coordinator in Supervisor lifetime ownership. Persist pending+barrier before stopping users or acknowledging. If durability is uncertain, keep closed and unknown, retain/join the registered owner or invoke isolation; never expose partial result. Existing CloseData/exec wire bytes stay canonical and independent.

Every registered execution, including acceptance-before-monitor-spawn, belongs to that set. `beginStartLocked` and closeRequested arbitrate under the original Execution lock:

- Stop wins before startCommitted: no cmd.Start may run. Await the original start owner joining; record task disposition never_spawned. No fake RootPID0 exec local_terminal, no removal from the evidence set before join.
- Start wins: await the SAME in-flight Start completion; install/use its original monitor registration and sole cmd.Wait. Do not allocate replacement monitor or claim absence from RootPID0. A failure without complete proof remains unknown unless the original owner proves no process ever started.
- Running monitor: send the existing stop request through its original control owner, then await original result/EOF, ownerDone and sole waitDone/success. A monitorCancel write/ACK or context cancellation is not completion. Do not add another Wait4/cmd.Wait or output reader.

After every owned execution has a complete disposition, fresh namespace proof is mandatory. On monitor disappearance, output-loss isolation, malformed result, unjoined owner, unexplained process, kernel change or journal uncertainty, do not issue terminal. Existing authenticated exec/query semantics and isolation policy remain; user quiescence is not allowed to convert their unknowns into local_terminal. Bounded foreign writer/OS-call limitations remain explicit.

## 4. Coordinator lifetime and shutdown — selected D1

Proposed single absolute budget: capture monotonic `t0` before first pending IO while fixing lifetime ownership; arm independent absolute isolation before potentially blocking IO; success must complete all stop requests, original joins, namespace proof, terminal persistence and atomic signing by `t0+31s`. No renewal extends this deadline. Monitor's existing fresh30s cleanup allowance remains unchanged, but it shares the remaining aggregate opportunity: a monitor receiving cancellation late can fail the aggregate deadline despite its own valid cleanup budget. This is a safety deadline, not a promise every valid quiesce completes in31s.

Stop request fan-out must use the one shared deadline, not64×1s serialized allowance. A finite worker may issue nonblocking/short-deadline writes sequentially within a proposed1s aggregate stop-delivery phase; any blocked control pipe causes unknown. Request handlers remain5s, with real EOF; ACK is emitted only after durable acceptance and supervisor lifetime registration. Lost ACK leaves the same worker/attempt and queryable diagnostic identity.

Ticket or caller context expiry after durable acceptance cannot abandon owned irreversible cleanup. Fresh authority is required for every future phase, not for finishing a previously accepted bounded stop. One worker, one deadline timer and bounded original owner references exist only while active; no idle goroutine/ticker/Watch. Shutdown stops accepting borrows, suppresses new receipt signing and joins this same owner before journal/key destruction; no second drain coordinator or new31s wait budget on each Close call.

D1 is load-bearing: current isolation helper can schedule up to another30s from invocation, and an original Start/journal syscall can be unpreemptible. Therefore this draft cannot claim the existing implementation gives a hard31s lifetime merely by waiting with a timeout. Selected required change: integrate an absolute quiescence failure deadline with the existing independent PID1 isolation owner, choosing the earliest registered deadline and never extending it. At expiry, atomically forbid success/receipt; report unknown and terminate PID1 via existing isolation outcome. No lock-dependent waiter is allowed to delay that fallback. Cooperative completion joins all owned callbacks; fallback process exit is not a signed drain proof. Exact OS scheduler/uninterruptible-call limits remain; no “all joined” claim on failure. If this absolute integration is not approved/feasible with current privilege/kernel contract, async acceptance cannot meet the proposed lifetime: narrow or block this unit instead of detaching a worker or changing the budget silently.

Atomic receipt signing must run under journal mutex, rechecking clean live installation, fixed closed barrier, complete terminal state and current exact runtime certificate/key, then post-check context/certificate before returning. Cold Open is diagnostics-only; restart changes Boot and cannot reconstruct active coordinator/capability or sign historical terminal as current success.

## 5. Actual whole-namespace proof

New launcher API proposal: `(*KernelBoundary).ObserveNoUserDescendants(ctx context.Context) (UserNamespaceQuiescenceObservation,error)`, process-local/self-bound and no execution authority. It is callable only after USERS admission irrevocably closed and original registered waits joined; these preconditions remain supervisor-owned and cannot be set by booleans supplied over transport.

Validate actual current PID1, namespace inode identity/proc mount view, cgroup membership and original kernel/contract seal before and after a bounded4096 numeric-process scan. Read each process through fixed nofollow/pinned proc directory FDs with strict bounded file reads; enumerate only task-needed identities, no arbitrary path/filter/PID. In eligible topology require no process other than PID1 at terminal census (threads belong to its original process). Do not exempt matching root/user UIDs or a familiar comm string. Then require non-reaping `Waitid(P_ALL,0,...WEXITED|WNOHANG|WNOWAIT|__WALL...)` to return ECHILD. A zero wait result is not ECHILD. Never consume a status owned by cmd.Wait. Check boundaries again and return zero observation on any failure.

Do not call monitor Drain as PID1: that API has a different role/sole-wait contract. Kernel/proc/cgroup evidence must be actual on supported Linux architectures and demonstrably allowed by the unchanged minimal capability/seccomp/LSM contract. No namespace/cgroup mutation or new privilege. More than4096 processes, PID reuse/vanish ambiguity that prevents completeness, unexplained child/process or a mounter in this namespace returns unknown. The finite scan is not an inventory/payload API. Its success is local sender quiescence only, not FUSE or remote settlement.

## 7. Operations observation and dual-drain prerequisite

Private self/origin/current-claim-bound cursor pins exact task/runtime/birth and last key; no serialized/public cursor authority. Each page transaction compares all original8 permanent fences and exact claim/guard plus identity/restore. Both branches have real nonempty Range reads; successful branch uses fixed operations prefix/cursor suffix, ascending key sort,limit16,nonserializable/current revision. Do not reuse an old revision across pages. Validate outer/nested response headers/cluster, positive/nonregressing revisions, exact prefix/range/key order/more/count limits and immutable leased strict records. Return owned data only, <=80KiB total keys/value/envelope accounting; remote oversize is error, not truncation. No result on malformed or partial response.

Pages are progress diagnostics; they do not aggregate to an atomic zero count. Permanent destroying control blocks all later legitimate BeginOperation commits, including requests prepared before destroying but sent later. Original token disappearance can happen between pages. After a pass, a NEW full-prefix limit1 current linearizable transaction under complete original claim/fences must be empty; if nonempty, return pending without effect/deletion. Monotonic local claim/context checks bracket every RPC; no claim loss resurrection. A native KeepAlive already sent before destroying may delay expiry; only actual current Range decides absence.

PrepareAfterDualDrain additionally loads/pins the exact original immutable quiescence intent/Stage receipt, verifies exact freshly authenticated terminal target receipt and same current task/runtime tuple, and checks current claim before and after final empty transaction. It may use a new current claimant only for this NEW local prerequisite after historical terminal reconciliation; it never adopts old send capability. This recovery boundary is selected explicitly: only a new local prerequisite, never original send authority. Final transaction must also pin the quiescence intent/receipt revisions; its read-only comparison budget must be counted, including response reads, before implementation. The returned opaque prerequisite carries current claim, exact evidence digests and empty observation revision; it is not a bearer permit. Future sync/flush preparation must recheck its original claim/fences and proof, because time can pass immediately after return.

Do not add a new TaskCheckpointState. Existing pending/needs_reconciliation plus a detail digest can record conservative progress under per-update CAS, but cannot replace typed retained evidence. No task worker scheduler, uncontrolled poll loop or per-idle-runtime maintenance is introduced.
