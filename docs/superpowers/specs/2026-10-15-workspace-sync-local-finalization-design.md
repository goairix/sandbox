# Workspace Local Whole-Sync Finalization Design

Scope: one complete local-provider functional unit on accepted f5d0de1; no runtime termination, owner release, cloud provider, main wiring, or archive reclamation.
The public result is owned diagnostic data and a durable reference, never permission. Existing regular recovery and v1/v2 validators stay intact.

## Entry and records

1. Add `Backend.FinalizeTaskWorkspaceSyncLocal(ctx, *TaskClaim, slot uint32, *controltransport.Destination, *launcher.KernelBoundary) (TaskWorkspaceSyncLocalFinalizationResult, error)`.
   Result: `Checkpoint *TaskWorkspaceSyncCheckpoint`, `Completion *TaskWorkspaceSyncLocalCompletionReference`, `LocalComplete bool`, and bounded counters for this invocation. Reference: Task, CreateRevision, SHA256 of canonical completion bytes. No public source, writer, callback, witness, or reconstructible capability.
2. Private full source uses the existing registered recovery source/lifecycle with explicit `regularOnly/fullLocal` admission mode and a private irreversible `effectsSealed` state; it does not convert caller diagnostics to authority.
3. Add fixed task keys using `taskKeyParts`: `tasks/<TaskID>/workspace-sync-local-progress` and `tasks/<TaskID>/workspace-sync-local-complete` (under existing namespace/partition prefix).
   Both have Lease=0. Progress v1 is mutable, strict canonical JSON, max 16384 bytes; complete v1 is immutable Version=1/Create=Mod, max 8192 bytes. Point reads only.
4. Progress binds Task/birth, original final-sync/archive command revisions and digests, manifest/store/root/target, plan/archive and budget through ONE domain-separated immutable binding digest computed from the loaded canonical context; also current writer claim, phase, frozen regular-checkpoint revision/digest, metadata intent identity/birth, and final physical evidence digest. Do not repeat the full manifest/Local or user-sized namespace in progress.
   Phase graph: `regular -> metadata -> effects-done -> sealed`. No backwards phase transition; restart may repeat work inside metadata. Empty regular checkpoint is explicit and valid for archives without regular entries.
5. Progress also contains a bounded temporary-mode restoration ledger: one canonical relative path (<=4096 decoded bytes, canonical standard base64 in JSON), <=128 ancestor component-end offsets, inode numbers and original modes. Same dev/UID/GID/mount are inherited from the pinned root. Compact integer tuples, no path-per-frame duplication.
   Maximum ledger path encoding is5464 bytes; each `[end,ino,mode]` <=31 bytes, array <=4097 bytes. Bound the non-ledger canonical projection (including keys/punctuation) to4096 bytes: total <=13657 bytes, below16384. Base64 avoids Go JSON HTML escaping turning4096 angle brackets into24576 bytes; ordinary valid path rules still apply after decoding.
   Only non-archive directories that must survive because they contain excluded descendants need original-mode entries. Archive directory final modes come from the verified archive; wholly removable subtrees need no restoration ledger.
6. Add a SEPARATE strict private v3 wire in the SAME `workspace-sync-recycling-intents/<BudgetID>/<IntentID>` family and existing fixed slot: kind exactly `local_metadata_pass`, provider exactly local.
   Bind Task/claim, budget, immutable manifest/plan/archive/target context and initial progress birth; no arbitrary effect/path/list or regular-file-body authority. Its ONLY effects are archive-directory creation/type repair, policy-authorized pruning, temporary traversal modes, and archive-directory final modes.
   Cap at configured MaxIntentBytes (4096..16384); preflight actual maximum encodings before progress/effects. Keep existing slot v2 wire, v1/v2 intent validators and public readers unchanged; a private version dispatcher recognizes v3 for full recovery only.
7. One metadata pass occupies ONE existing slot after all regular charges are drained. It is deliberately a bounded plan-scoped pass, not one slot per directory or one new key per effect. Fresh recovery preserves its immutable IntentID/bytes/birth and old unknown outcome, and produces new domain-separated physical evidence.
   Evidence v1 binds intent digest/birth, fresh claim, actual local target, regular checkpoint, phases completed, operation counts and streaming transcript digest. The transcript covers mkdir/unlink/rmdir/temp/final chmod, affected path, observed inode/kind and resulting mode/absence; it is diagnostic evidence created only by the registered executor.
8. Complete binds the immutable original context, final physical root attribution, final progress revision/digest/evidence, frozen regular checkpoint, completion claim, and protocol domain. A private strict reader validates generation/key/context and returns copied data; it does not grant release.
   The later release consumer must reconstruct its own current pins and compare this exact immutable key Create/Mod/Value/Lease=0, plus matching task/final-sync/target context. Neither nil error nor `LocalComplete` is release evidence.

## Seal proof and admission fixes

9. Existing `registerRecovery` excludes all same-Task live recovery owners and recovery spools; spool removal waits delivery owner, source `done`, metadata owners, and actual file Close. Store close joins owners before releasing its actual root FD/flock.
   CURRENT GAP: `reserveRecovery` can register a new spool after a recovery owner. Fix it under the SAME `taskArchiveStore.mu`: reject matching live recovery owner and matching registered original spool before charge, disk creation or metadata IO.
   Store each original spool's immutable seed Task identity at registration (including quarantined initialization), so comparison does not depend on a later bound diagnostic. Use fixed slot scan plus bounded existing spool set; no Task map.
10. `PrepareTaskWorkspaceSyncSource` checks progress/complete under current native claim after its existing `spool.consumer` registration and before verify/cursor/local IO. The original spool remains registered through all source/local-put joins.
    `prepareTaskWorkspaceSyncRecovery` checks both fixed keys after `registerRecovery` and current-claim guard, before first local metadata effect; full mode later validates them against loaded manifest/history. Public regular-only entry refuses ANY progress or complete record, including malformed/foreign-context records.
    Full entry creates progress only while holding this unique physical source. Sources registered earlier prevent its admission; sources registering later are excluded until its actual Close, then must see progress/complete. New original spool admission also performs the fixed-key refusal before delivery can yield a source.
11. Thus no complete-absence compare is added to each existing GC: completion can be created only inside the sole full owner, after its local effects are irreversibly sealed and joined. Registration lasts through completion transaction, readonly postguards, target/archive Close and source `done`.
    This requires every cooperative writer for this task to use the SAME unchanged recovery-store root and upgraded admission paths. Root inode/flock alone is insufficient; retain same-root checks, per-Task exclusion, existing all-history/current-claim fences and physical joins together.
    Mixed old binaries, alternate recovery roots for the same task, root replacement, or out-of-band same-UID mutation are outside this proof and must remain unavailable/pending, not automatically reopened.

## Execution and restart

12. Own source -> current claim guard -> load and verify cold bound archive -> historical dual drain + all 50 pins + authenticated producer query -> exact local target -> strict progress/complete read.
    Keep original claim/manifest attribution; historical claim records must precede the fresh claim, or be the exact current claim. New records may use current claim only after its birth. No Lease on durable records; current authority still compares actual claim/guard Lease and local deadline/context.
13. Before first effect perform a PRIVATE full-archive DFS/preorder validation. `launcher/workspace_archive_linux.go:archiveWalk.directory/child` emits directory header followed by its entire subtree; current accepted producer guarantees this order.
    Validate with <=128 active ancestors: each entry's parent must remain on the active stack; a closed subtree cannot reopen. Keep old TAR validator/accepted old APIs unchanged. A structurally accepted but non-producer-order cold archive is refused by this new finalizer before effects; document this explicit finalizer constraint.
14. Create/capture progress `regular`, then run existing regular checkpoint continuation. New full-only preparation repairs all necessary archive-parent directories to temporary 0700 before regular IO; final directory modes are deferred.
    For S=1 occupied legacy v2 put, do NOT allocate metadata intent: an explicit fresh local repair umbrella is anchored to that exact immutable charge + intended archive entry + full plan + current native authority.
    It may repair necessary archive-directory ancestors (including unlinking a blocking owned regular file), or remove a conflicting directory subtree at the EXACT intended regular-file path. It may not prune unrelated extras.
    Any exclusion equal to, above, or below a path that would be destroyed makes that type replacement fail conservatively before removal; excluded descendants are never traversed/deleted. `DeleteExtraneous=false` still permits necessary explicit type replacement only.
    Fresh regular-repair evidence gets its own new domain including metadata transcript digest; never modify old intent, old unknown result, or accepted ordinary recovery completion encoding. Existing regular-only API keeps its narrower behavior.
15. After regular cursor EOF and no same-Task charged intent in the fixed S scan, freeze its checkpoint and advance to metadata. Allocate or recover exactly one v3 metadata intent; other-task charges remain untouched.
    Recovery dispatches the persisted phase before invoking regular's v2-only slot reader, so a v3 occupant is not accidentally interpreted as a legacy regular put.
16. Metadata pass A streams archive once, ensuring all included directories exist with temporary 0700, including empty directories and file-to-directory replacement. Workspace root is never chmodded: it stays operator-owned 0700 regardless of TAR root mode.
17. Metadata pruning runs only when DeleteExtraneous=true. Traverse actual local tree using descriptor-relative, NO_XDEV/NO_SYMLINKS/NO_MAGICLINKS resolution, <=128 depth and fixed 32768-byte Getdents scratch, never ReadDir(-1).
    Archive membership/kind uses existing 33-byte SHA256+kind index; exclusions use bounded literal policy. Prune excluded subtrees without opening them; retain their necessary ancestors; remove unrepresented nonprotected files/subtrees bottom-up.
    One shared page buffer plus per-depth FD/cookie state and one path buffer; do not retain one page/path per depth. Validate native directory cookies/entry advancement on supported filesystems; restart a traversal after process crash, never trust cookies as durable progress.
18. Before temporarily changing a retained non-archive directory, durably CAS its inode/original mode into progress under v3 charge guards; only acknowledged/strictly resolved ledger allows chmod. Pop ledger only after actual restoration+fsync+Close and readonly identity checks.
    After a crash, fresh source first reopens ledger ancestors using their pinned inode identities, restores deepest-first, then restarts metadata passes. Ledger purpose is exactly `retain-original-mode`: entries are protected ancestor dirs, never authorized delete/type-replacement targets in this pass; missing/replaced ledger inode is therefore conflict, never chmod a replacement or infer old success. For removable nodes no restoration entry exists; fresh authority revalidates desired absence/shape from plan and observed inode before further repair. Archive dirs may reopen temporarily because their final modes are independently known from archive.
    This closes the otherwise missing crash case: an extra mode-0000 ancestor containing excluded descendants must preserve its old mode while sibling extras are deleted.
19. Metadata pass B streams archive DFS once, pushes each included directory's intended mode and descriptor, finalizes on subtree exit (postorder), and finalizes empty dirs too. No archive rescan per directory, no mode plane, no index/version/disk expansion.
    An interrupted mode pass restarts metadata, so already-finalized 0000/0555 dirs reopen via the same descriptor-anchored temporary traversal mechanism. No old per-directory success is inferred from path absence or final mode alone.
20. Linux helpers use private O_PATH inode anchors plus verified numeric `/proc/<currentPID>/fd` fchmodat fallback as the accepted regular permission repair does; add a separate directory checker permitting owned ordinary mode 0000..0777, without weakening old strict-0700 helpers.
    Parent/path/FD identity is rechecked before destructive syscalls; target entries are same UID/GID/dev/mount, directories have valid links, regular files nlink=1; symlinks/special nodes and mount crossings fail closed. Never bare workspace pathname chmod.
    Native guard precedes EVERY mutating syscall including temporary chmod/unlink/rmdir; readonly identity/root/archive checks surround it. Keep source+target registration until actual syscalls, fsync and all inode/proc/directory FD Close return.
21. After metadata EOF: ledger empty; all final mode restorations and child/parent/root fsync complete; all per-effect descriptors actually closed; readonly guards pass. Settle the v3 slot with fresh evidence, then atomically free slot/delete intent/update progress to `effects-done`.
    Seal physical-effect admission permanently; join operations/monitor without waiting on the current registered finalizer operation itself; actually close target FD. A private readonly root reopen/check/close path supplies subsequent postguards without resurrecting a mutable target.
    Under the STILL registered source, CAS `effects-done -> sealed` plus create immutable completion. Close remaining archive/source handles and return `LocalComplete=true` only after final readonly guards and actual Close succeed.
22. Fresh source finding `effects-done` performs readonly exact-context/root/history validation and joins its own target before creating completion; it does not replay physical effects. Finding valid completion similarly returns copied evidence after readonly validation and Close, without any mutation.
    Any native ACK loss makes that exact attempt read-only: compare canonical keys/generations to resolve, never repeat writes or physical work under the old attempt (including ledger push/pop). A fresh source with the same still-current claim, or a genuine fresh claim, may reconcile pending effects but creates independent fresh physical completion; old unknown stays unknown. Cancellation/claim loss/root change/Close failure prevents success; any already committed marker remains independently revalidatable, never deleted to retry.

## Exact transaction and resource bounds

    Progress create: 54+absent 1, write 1 =56 nodes. Phase/ledger CAS without charge:54+progress MOD/VALUE2, write1=57.
    V3 reserve:54+intent absent1+slot MOD/VALUE2+progress MOD/VALUE2, writes intent+slot2=61.
    V3 physical/ledger guard:54+intent CREATE/MOD/VALUE3+slot MOD/VALUE2+progress MOD/VALUE2=61 comparisons; ledger update1=62 nodes.
    V3 terminal:54+intent3+slot CREATE/MOD/VALUE3+progress2, write1=63 nodes.

    Completion:54+progress MOD/VALUE2+checkpoint MOD/VALUE2+complete absent1=59 comparisons, progress+complete2=61 nodes. Point reads and worst-case failure branch are independently preflighted within64.

    S=1..64 unchanged; archive index remains exactly33 bytes/slot, existing admitted I+4M (M=65536), spool metadata/disk caps unchanged. ## Binding interface and file clarifications

The accepted master design and repeated human continuation authorize this refinement and implementation; no new rollout or production release is authorized here. Baseline is f5d0de11c08a28ee71ac64db4279d04af94f8800.

The public result fields are exactly `Checkpoint *TaskWorkspaceSyncCheckpoint`, `Completion *TaskWorkspaceSyncLocalCompletionReference`, `LocalComplete bool`, `CompletedFiles, CompletedBytes, CreatedDirectories, RemovedEntries, UpdatedDirectoryModes uint64`. Counters describe this invocation, use checked increments, and never grant authority. The reference fields are `Task TaskReference`, `CreateRevision int64`, `SHA256 string`. Completion reading remains private, through the registered full source; there is no independent public permission-producing reader.

Publication revision binding is native, not a self-referential JSON field: the immutable completion stores the canonical sealed-progress SHA256; its reader requires sealed progress.ModRevision == completion.CreateRevision because both are written by the same transaction. An explicit prior effects-done revision/digest may bind the prepublication fence. Do not serialize the not-yet-known transaction revision into its own values or add a second publication write.

Empty regular progress freezes the already-existing initial TaskCheckpoint v1 KV revision and canonical value digest; its public WorkspaceSync Checkpoint remains nil. That record exists at task birth even for a directory-only archive. Keep positive CheckpointRevision and exact checkpoint MOD/VALUE comparisons; do not create a new old-checkpoint encoding, write a placeholder, or use key absence as the empty representation.

Every resumed mutable progress phase must establish a fresh native ModRevision before physical effects, including same-claim metadata recovery, to fence any old lost-ACK progress/ledger/GC transaction. A completed-marker call remains read-only. Resuming an existing regular phase under the same claim is refused until a genuine new claim: the accepted regular GC has no spare comparison for this progress key, so only the old claim's irreversible loss excludes a late old GC before another repair. Initial progress creation is already guarded by absence.

Directory-only archives need original received-to-bound attribution without a regular body. Add private `PreparedTaskWorkspaceSyncSource.bindLocalFinalizationTarget(ctx, target)` and narrow spool binding support in the existing source/store files. Require real original source+target registrations, matching plan/workspace/worker/root, current native guards, existing metadata gate and actual IO joins; allocate no put slot/body and mutate no target. Preserve the old body-based `sealOriginalBinding` path and validators. Test received archive → original bodyless binding → actual original joins → cold finalizer; no handmade bound manifest. Production Backend assembly remains later work.
