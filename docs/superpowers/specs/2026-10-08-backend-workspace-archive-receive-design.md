# Bounded backend workspace archive receive core

Authority: approved `2026-10-06-etcd-state-management-design.md`; original Supervisor/TLS producer accepted at `54e5b77`. This is the private receiving core for the next original-backend final-sync sender. It grants no new public capability or provider effect.

## Requirements

1. A private original spool store owns a pre-existing absolute clean private directory under the backend's actual UID. Require empty directory at construction (bounded one-entry check); nonempty cold files refuse, are preserved, and cannot be ignored by a reset quota counter or reconstructed as authority. Linux/Darwin open directory and files with nofollow/exclusive semantics, verify regular file/type/owner/link/inode identity, and retain original descriptors. Unsupported platforms fail closed. No source filesystem extraction, caller-selected runtime path, spool cold reconstruction or public raw descriptor/path getter.
2. Trusted operator limits explicitly bound concurrent original jobs, per-job and total reserved archive disk bytes, logical entries (at most1million), and per-job/total index memory. Reserve before receiving any DATA; future sender must reserve before command bytes. Limits must be consistent, nonzero and overflow-safe; protocol archive ceiling is1TiB. Failed admission must not start IO. Resources scale with admitted active/retained jobs, not number of existing sandbox records; no idle timers/watchers/actors. Quota/IO failures never become successful sync or release proof.
3. Only the original reserved handle may begin a receive once. Stream original sealed Session archive frames into its private file synchronously, hashing every actual DATA byte including TAR PAX/padding/end. Enforce physical counts, chunk/total bounds, context/deadline, ordering and original completion attribution through the supplied original immutable ManagementVerifier/Destination and caller-retained expected context/digest/three times. Query-only receipt with no original DATA cannot create a new received archive. Require actual authenticated response EOF; never retry a failed frame or EOF check to discard malformed/trailing data.
4. After authenticated terminal+EOF, validate the physical spool TAR: fixed first workspace directory, canonical UTF8 relative paths under workspace, no dot/backslash/control components, depth≤128 and path≤4096; only directories and regular files, sanitized UID/GID0, no links/devices/sparse/global PAX or unsupported metadata; exact regular declared sizes/body and terminal archive end. Count logical entries (PAX support records are not logical entries) and compare actual count/bytes/SHA256 with the authenticated summary. Reject duplicate names and missing/non-directory parents. Source Readdirnames pages are unsorted: no global sort or lexicographic order requirement.
5. Duplicate/parent index has a bounded allocation from admitted index budget, not an unbounded map of path strings. Use fixed SHA256 path entries and kind bits in a fixed capacity table (load≤1/2, power-of-two slots); reserve exact backing byte length, bound probes and check context. Hash collisions conservatively reject; do not claim literal whole Go RSS equals this index budget. Temporary TAR metadata/buffers must remain bounded; Go1.25.6 tar special headers are limited to1MiB, and sparse/unsupported PAX keys must be rejected before body processing. Never allocate by untrusted declared file size.
6. Successful result is a private original-instance sealed received-spool witness with copied diagnostics and original expected attribution; copied/zero/foreign handles refuse. It is not durable proof, current claim/KV authority, upload settlement or safe release. No external provider call starts here. On uncertain network/receipt/EOF, return no verified witness; any retained bytes stay original unverified diagnostics under the same bounded reservation. A future original sender may decide bounded recovery policy, but this unit adds no DATA resend, query laundering or public promotion from summaries/files.
7. Close seals registration, cancels original receive and waits actual owner IO before descriptor destruction/unlink/quota refund. Concurrent/repeated close joins the same owner; do not hold store mutex across network/file callbacks or physical waits. Store shutdown waits original spools, including verified retained ones. Context cancellation is not proof an arbitrary IO callback returned. Cleanup only original controlled names/identities; uncertainty preserves files and conservative accounting.

## Verification / scope

Pure consumer tests use actual private temporary files and real pinned mutual TLS with genuinely signed protocol receipts, testing received bytes/count/hash/PAX/EOF and hostile data/signatures. Fixture signer is a consumer fixture, not actual PID1 or backend current KV send proof. Test admission/exhaustion/refund, private modes/identity/symlink/link/copy refusal, concurrent actual receive/close joins, oversized/truncated/trailing/malformed paths/types/sparse/duplicates/parents/count/hash and canceled/late contexts. Run only new receive/spool focused selectors with race; vet/compile may include the package but do not execute old accepted native selectors. No Docker/native consumer required in this pure core unit.

Original backend final-sync command reservation/issuer/current KV fences, claim renewal during long receive, original recovery, verified artifact consumption, per-real-HTTP-attempt settlement, production wiring/scheduler/FUSE/collector, big-N capacity, deployment/restore/Redis removal remain subsequent work. Capacity limits are enforceable admissions, not performance/capacity acceptance. Long-idle credentials remain pending.
