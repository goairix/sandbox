Authority: approved `2026-10-06-etcd-state-management-design.md`. This follows the bounded original receiving core at `bd46b2b`, independently accepted at `5bf4188`. Existing feature branch `codex/etcd-state-management` remains authorized. This unit creates an original immutable command prerequisite; delivery, provider effects and release remain subsequent work.

## Requirements

1. Add purpose-specific `TaskWorkspaceArchiveIssuer` with `Certificate(context.Context) ([]byte,error)` and `SignWorkspaceArchive(context.Context,string,controlprotocol.TaskWorkspaceArchiveTicketClaims) ([]byte,error)`. The digest selects the exact immutable certificate. Dependencies are operator supplied, immutable, context honoring and concurrency safe. Reuse existing PublicationTrust and controlled AuthorityClock. Backend construction validates configuration, including typed nil, invokes neither callback and retains no signing private key. Missing issuer/trust/clock cannot create a command. No new trust root installation.
2. `PrepareTaskWorkspaceArchive(ctx,c,prepared,destination,sessionDuration)` requires the original current TaskClaim, original PreparedTaskQuiescence and the same successfully committed original `ReserveTaskFinalSync` draft. Session duration must be greater than30seconds and at most1hour; derive a fixed start window (NotBefore=observed UTC minus1second, NotAfter=observed UTC plus20seconds, SessionNotAfter=NotBefore plus sessionDuration) from the first trusted observation. Certificate and runtime must cover the full original interval. Original fixed prerequisite deadline bounds all preparation callbacks/native writes. Renew/retry never revives an expired prerequisite or changes the command ID, ticket, times, issuer, final-sync attempt or plan.
3. Construct TaskWorkspaceArchiveContext from exact validated native task/claim and original dual-drain/final-sync pins. CommandID is the original final-sync AttemptID. Bind exact original quiescence context, ticket digest, authenticated receipt wire digest, native quiescence intent revision, native final-sync revision, plan digest, actual original runtime and newly pinned issuer identity. Historical quiescence may belong to an earlier claim; Current must name the present original claim, respecting protocol lineage. Callers cannot supply arbitrary context, times, receipt summary or command bytes.
4. Pin exact copied issuer certificate before signing; register its immutable metadata only under fresh native original task/claim and dual-drain/final-sync fences. Recheck current original fences before/after each external callback, native read/write and trusted-clock observation. Verify returned ticket through original Backend verifier against retained expected context and all three exact times. Never borrow old successful native write authority for a later read. Freshly revalidate original quiescence plus whole operations-prefix emptiness (bounded limit1 linearizable Range) before committing a command, not merely an old emptyRevision.
5. Persist one permanent immutable fixed task key `workspace-archive-command`: version1, canonical bounded JSON (<=64KiB), lease0/native version1/create=mod, exact task/final-sync attribution and revision, expected claims, exact certificate identity/native issuer revision, ticket and original quiescence receipt bytes. Command create revision must exceed original claim, quiescence and final-sync native revisions. Strict codec rejects unknown/duplicate fields, nulls, noncanonical/oversized values, corrupted attribution or key/revision lineage. Use exact protobuf request/reply preflight, <=64 literal transaction nodes and <=256KiB mutation budget. Do not relax existing shared caps; bounded point reads and immutable native MOD pins can keep composition within them when exact records are freshly validated.
6. One private draft per original final-sync owner seals preparation. Consume writeAttempted before first command Put. Retry arbitrates the exact same value/revision; response loss or canceled/expired owner may return committed diagnostics with an error but never a new Prepared or replay authority. If the original Put response was fully lost and no original native revision is known, pin a first exact immutable recovery for diagnostics only (OutcomeCommitted with error/nil Prepared), then reject later ABA; an identical pre-recovery delete/recreate cannot prove original send authority. A known original successful revision may reuse the same original Prepared while current original authority remains live. Absence after ambiguous send stays unknown. Conflicting/recreated native key/issuer/claim/restore epoch refuses. An original instance-sealed PreparedTaskWorkspaceArchive retains private Backend/claim/draft identity; zero/copied/foreign handles and historical Load results cannot manufacture it. Public result/reference is diagnostics only, no ticket, private key, path/FD, live guard, Stage or release getter.
7. No application archive bytes, spool receive, provider call or production wiring in this unit. A later original delivery owner must pre-reserve the bounded spool, freshly check native authority after handshake and immediately before command bytes, allow claim renewal during long receive without holding c.mu, retain the fixed session deadline, physically cancel/join after loss, then freshly check current pins/operations before any verified-artifact consumption. No idle actor/watch/timer per existing sandbox. This unit must not be reported as those delivery requirements being complete.

Current existing historical quiescence query and this preparation share one Destination. Existing QueryTaskQuiescence pins its historical issuer credential; therefore the purpose-specific archive signer must select the same actual still-valid certificate as that Destination, with full archive session coverage. A different valid issuer certificate refuses before command Put. This bounded unit does not implement certificate rotation. Coordinated historical-query/TLS/issuer/runtime on-demand maintenance remains mandatory before production, especially for long-idle sandboxes; do not weaken Match or silently claim separate destinations alone resolve historical pinning.
