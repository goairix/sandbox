# Workspace archive user access at open

Approved parent: `2026-10-06-etcd-state-management-design.md`; required unresolved read policy: `2026-10-08-pid1-workspace-archive-verification.md` CV5. This elaborates that approved requirement without production deployment or renewed capability grants.

## Chosen behavior and alternatives

Keep PID1 real/effective/saved UID/GID root and capability mask0xe0, no DAC bypass capability. Add a user-read source constructor; temporarily change only the current locked OS thread's filesystem UID/GID and supplementary groups around a fixed readonly open syscall, verify restoration before returning an FD, then perform normal archive processing. Never invoke a destination writer, arbitrary exported callback, or process spawn while temporary identity is active. KernelBoundary.mu serializes these transient scopes with existing all-thread kernel validation. LockOSThread is established before mutation; pinned Go1.25.6 runtime uses a clean template thread for new threads from locked threads (`runtime/proc.go` newm and LockOSThread), preventing credential inheritance into runtime worker creation.

Rejected: add DAC_OVERRIDE/READ_SEARCH (enlarges privilege contract); process-wide setuid/setgid (breaks management identity); dedicated trusted user archive subprocess (requires a separate launch/join protocol and weakens the already selected no-subprocess primitive). The selected narrow open scope uses existing SETUID/SETGID privileges. Linux [setfsuid(2)](https://man7.org/linux/man-pages/man2/setfsuid.2.html) and [setfsgid(2)](https://man7.org/linux/man-pages/man2/setfsgid.2.html) document filesystem-only identity and silently failed setters: setter return alone is insufficient, readback is mandatory. These Linux-specific interfaces are discouraged generally; this constrained CGO0/thread-pinned use is explicit and requires native evidence.

## Interface and authority

`(*KernelBoundary).OpenWorkspaceArchiveAsUser(ctx context.Context, observation *UserNamespaceQuiescenceObservation, uid, gid uint32) (*WorkspaceArchiveSource, error)` requires original/current PID1 boundary, original same-boundary observation and uid/gid each1..2147483647. Linux support only amd64/arm64 and CGO0 runtime; other platforms/unsupported runtime fail closed before credential mutation. Preserve the accepted root-mode OpenWorkspaceArchive API and archive semantics. Store the chosen UID/GID privately in the original source; copies remain invalid. Root-mode source must retain its current behavior and syscall path.

UID/GID arguments are **access policy, not authentication or authority**. Future activated Supervisor must use its verified immutable birth/activation user identity, not caller-selected network fields. This task does not bind a task/claim/producer, close gates, authorize remote effects or release owners. Archive summary remains diagnostic. Permanent USERS/DATA closure and spawn exclusion remain the integrating Supervisor's requirement.

## Narrow native scope

- Only readonly fixed `/workspace` root open and pinned-root relative openat2 child/probe/revalidation opens use the user scope. Keep all accepted no-follow/CLOEXEC/nonblocking/directory/root-pin/NO_XDEV/BENEATH/NO_SYMLINKS/NO_MAGICLINKS protections. Opened FDs already passed user access checks; no caller path, flags or privileged arbitrary-function API is added.
- Precompute path/flags/open-how data outside mutation. Establish LockOSThread while root, own original KernelBoundary.mu, check context and original current identity. Direct current-thread raw syscalls only: no AllThreads setters or process-wide wrappers. Use supported ABI, stable pointers/KeepAlive and bounded supplementary group storage <=64.
- Before mutation require current filesystem UID/GID0, expected P/E/I0xe0, no ambient/bounding authority changes, root real/effective/saved IDs and dumpable0; controlled `/proc/sys/fs/suid_dumpable` must equal0. Reject unsupported/unsafe state before any open. Preserve and later compare the original supplementary group list. Do not expand accepted caps, kernel validators, seccomp policy or role contracts.
- Clear supplementary groups, set filesystem GID then UID to the chosen user, read back exact UID/GID and empty groups before opening. A failed/silent refused setter must never allow opening as root. Setter queries using -1 must be checked correctly. Do not assume nil errno means identity changed.
- Execute only the fixed readonly raw open/openat2, retaining its error/FD. Restore filesystem UID0, GID0 and exact original supplementary groups on every path, including entry refusal, open failure, cancellation, panic and native syscall errors. Verify restored filesystem IDs, groups, unchanged capabilities, real/effective/saved root identity and dumpability before releasing mutex/OS thread or delivering the FD. Do not call full ValidateCurrent recursively under its mutex.
- If complete restoration cannot be verified, **terminate actual PID1 immediately with fixed exit70** using a nonblocking process-exit path; do not return, unlock/reuse the dirty thread, invoke writer or grant success. Do not offer an injectable public fatal callback. Process death/unknown retention belongs to future integration; exit70 alone is not a remote-settlement or owner-release proof.
- If identity setup fails but restoration succeeds, return a conservative error, close any opened FD if needed, and preserve ordinary source single-consumption/zero-summary rules. The source still revalidates original census/kernel/root/context at completion. Caller writers, file reads, directory enumeration, TAR work and user callbacks happen after restoration. A blocked open keeps the original scope occupied; no forced cancellation/join claim. Existing fallback isolation exit does not acquire KernelBoundary.mu.

## Verification and limits

Use a new focused native fixture, same already-local pinned image and restrictions as the accepted source, fresh labeled volumes and bounded attach/actual terminal/wait/cleanup. Select only new identity tests; do not replay accepted archive/kernel tests. Test-only CGO0 user helper (separate protected binary) runs with actual UID/GID1000 and no groups/caps to create fixed700dir/600file, exits and is joined before census. Helper has fixed prepare/clean paths under the fixture and no product use.

Native positive RED must compile with AsUser all-reject stub and fail actual private-content success; preserve exact stub snapshot and full evidence. GREEN verifies default root source actual EACCES, user1000 success, wrong user2000 denial, invalid/copy/origin cases, context/writer failure zero summary, all-root credentials at writer callback and after return, original group/cap restoration, and root-group-only file denial (supplementary group stripping). Exercise syscall entry refusal in a separate restricted container and verify clean restored root state. A separate native PID1 fixture installs a test-only NNP/TSYNC seccomp filter denying setfsuid(0): entry to1000 succeeds but restoration fails, and actual terminal exit70 is required with no returning source/writer/success. These filters do not change product seccomp policy or add privileges. Capture each terminal and exact cleanup, including deliberate exit70, rather than counting it as Go PASS.

Host validation tests/race and vet plus Linuxarm64 CGO0 compile complement actual native cases; host race cannot cover excluded Linux identity code. The native scope requires CGO0 and supported Go runtime template semantics; no Linux race or hostile foreign C threads claim. No provider/FUSE data settlement, authenticated source stream, capacity/maximum-resource proof, deployment or production migration is delivered. Existing blocked IO, privileged snapshot/root-remount limits remain.
