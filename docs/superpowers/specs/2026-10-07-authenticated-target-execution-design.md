# Authenticated target activation and real execution design

This unit implements the next physical part of the user-approved native etcd migration, on `codex/etcd-state-management` from `feat/workspace-fuse-mount`. The goal remains a complete Redis replacement and bounded work with large existing sandbox count N. The earlier local confinement/drain unit is complete at4c5c356, independently reviewed with complete permanent evidence. This unit must finish with actual PID1/monitor/user execution from an original PreparedExecEffect, not another passive diagnostics milestone. Production Manager, Docker/Kubernetes image wiring, lifecycle/task/remote settlement, scheduler/collector/GC and final Redis removal remain subsequent required phases1–5 work; no deployment or online mixed backend is introduced.

## Chosen architecture and alternatives

Use a root-protected Unix control socket, immutable byte-only relay, and TLS1.3 end-to-end between the original backend and the actual sandbox PID1. The relay owns no API/target private key and executes no user argv. A freshly bootstrapped PID1 creates a nonreused UUID BootID and runtime delegate key; an operator activation authority certifies an independently observed exact runtime UID and this current birth. The target independently pins its birth/key/user/security contract and current authority/issuer/gate. Authenticated delivery from the trusted original backend supplies dynamic operation context, after fresh original etcd fences and time checks; the target checks that context against its independently installed static activation and signed full request.

Rejected alternatives: a root Unix peer plus ticket alone lacks authenticated committed-delivery context; historical etcd records cannot reconstruct original execution authority. Running commands in a sidecar changes user namespaces/cgroups and violates the original execution contract. A general public payload/transport callback would expose Prepared internals and is not introduced.

On monitor failure the target closes admission, retains unknown, stops and joins registered management owners where possible, and terminates its own PID1 with a nonzero exit. Linux terminates remaining processes in that private PID namespace when its init exits; this is conservative whole-runtime isolation, not a business End or remote-write settlement. A future lifecycle worker must observe exact runtime termination and remote settlement independently. Primary reference: [pid_namespaces(7)](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html). Availability costs are loss of this sandbox and original-quota failure; no new namespace/host privilege is requested.

## Trust, birth and activation

The operator, not a user API request or command issuer, holds the root activation signing key. Deployment-pinned ManagementVerifier roots/binding are immutable. PID1 uses BootstrapPID1 and actual ValidateCurrent before publishing its Hello. BirthContext contains BootID, fresh runtime Ed25519 public key, independently configured original user UID/GID, independently bound NetworkAllowed and security ContractDigest. ContractDigest binds immutable image, launcher version, IPC/security/namespace/cgroup/network/mount topology and user identity. Native fixtures derive the image/resource/security assertion from actual Docker inspect; later production attestation must do the same through the exact runtime adapter/current original creation claim. A tag/config-provided UID is not that attestation.

Root-signed TargetActivationClaims include version1, role `target_activation`, root key ID, nonreused ActivationID, TrustBinding, SandboxID, WorkspaceHash, Generation, exact RuntimeReference (BootID=current canonical UUID), DataGateEpoch, user UID/GID, NetworkAllowed, ContractDigest, runtime identity certificate digest, selected command issuer certificate digest and UTC NotBefore/NotAfter. Lifetime<=1hour, additionally bounded by both delegate certificates. New wire uses snake_case nested binding `{namespace,authority_id,target,restore_epoch}` and identity `{sandbox_id,workspace_hash,generation,runtime}`; runtime stays `{id,uid,boot_id}`. Private wire DTOs preserve existing public Go types/serialization. Add only strict boolean schema support for NetworkAllowed, without changing existing schemas. Verification authenticates the root claim before using its externally observed runtime tuple, pins the independent local birth/user/network/key/contract, verifies both delegate certificates against the authenticated tuple/current binding/clock and requires independent root/runtime/command keys. It returns opaque TargetActivationEvidence with copied diagnostics; it is not a generic raw execution token.

Activation install is permitted only on the freshly created live journal handle, never a reopened handle. It persists a separately bounded activation file (<=16384bytes, included in byte/file accounting) and exact immutable binding and open gate through the protected journal under its lifetime lock, then marks this live Supervisor active. No user call, unknown historic record or reopened journal can activate. Same activation retry may confirm existing state; different activation/current birth mismatch fails closed. Every boot is fresh: existing state for another boot is never adopted or automatically repaired. Startup with uncertain/missing required state stays closed. Operator recovery/rotation/reopen with fresh task authority remains separately required; this first unit supports one installed activation/selected issuer until close, avoiding a false partial rotation protocol.

## Controlled clock and TLS key custody

Move existing ClockObservation and AuthorityClock definitions into controlprotocol and retain etcd aliases, preserving current provider contracts/tests. Add an authenticated signed-clock IPC client/service: fresh UUID challenge and audience plus TrustBinding on each call; a separately deployment-pinned dedicated Ed25519 clock public key authenticates fixed `authority_clock_observation` domain/purpose, binding, nonce, audience, UTC and uncertainty. Key is independent of operation/activation delegates. Clock wire uses the same new snake_case binding DTO. Client measures entire monotonic call elapsed, rejects uncertainty+elapsed>1s, wrong nonce/binding/key/shape and late context, then returns an observation accounting for elapsed conservatively. Service takes an explicit trusted context-honoring AuthorityClock source; it never invents zero uncertainty/local wall trust. Underlying time synchronization/provisioning is an operator trust contract and a later deployment gate, not certified by a fixture source. Active calls only; bounded connections, closed on stop.

NewManagementTLSCredential copies a delegate private key and its custom signed identity certificate and proves key agreement; no private-key getter exists. Returned TLS configs must expose only an unexported immutable crypto.Signer wrapper, never raw private-key bytes. Its Sign accepts only crypto.Hash(0) and the exact64-space TLS1.3 CertificateVerify padding, role-specific `TLS 1.3, client CertificateVerify\x00` or `TLS 1.3, server CertificateVerify\x00`, and32/48byte transcript hash. Any operation/activation/publication/renew/clock payload signing request rejects; leaf creation uses the private key internally before the restricted signer is exposed. Generated self-signed single Ed25519 leaf carries no separate authority: peer authentication verifies its bounded DER, self-signature, non-CA/digitalSignature/exact role EKU, exact public key from the independently authenticated custom certificate, TLS version/ALPN/no-resumption and fresh certificate interval. Server demands a client certificate; client custom pin verification is complete even where standard CA/hostname verification is disabled. Both roles use VerifyConnection and disable tickets/cache. Client peer runtime tuple is from original trusted state, server peer issuer is from protected activation, never selected by peer leaf or request. Primary reference: [crypto/tls](https://pkg.go.dev/crypto/tls). Existing ExecCommandIssuer signing interface remains unchanged; a new separately configured opaque transport credential must match that exact selected issuer, without extracting a key from the provider.

## Durable acceptance, renewal and result records

Keep version1 unknown history readable. New version2 exec records have states accepted, local_terminal or unknown; full payload/ticket/stdout are never persisted. They retain exact original context/digests/window, latest accepted authority deadline, root/result scalar diagnostics and termination reason. Active journal configuration supplies an independently copied BirthContext, pinned ManagementVerifier and AuthorityClock together; absent all three preserves passive compatibility, partial/typed-nil configuration rejects. Install/accept/renew recheck the installed certificate, activation and evidence time against fresh controlled observations before and after dangerous persistence; late/unknown writes return no new registration or successful ACK and retain uncertainty. Initial acceptance creates a fresh record only while this live activated gate is open and exact expected fields match. Unknown/existing accepted/terminal history is deduplication/query state, never a reconstructed start capability. A retry with exact command/context/digests/window returns its state and cannot spawn again; conflicting bytes fail.

The accepting live Supervisor owns a private one-use start registration; consume it before monitor creation. Failure/uncertain persistence after acceptance stays unknown and closes target, no replay. Signed runtime receipts distinguish accepted, local_terminal and unknown; bind exact runtime/birth/command/operation/digests/epoch, root PID/raw status and local-drain success only where actually observed. Their signature domain differs from publication/start/renew; verification pins externally trusted accepted context/digests, original NotBefore/NotAfter and latest durably accepted authority deadline exactly before yielding opaque copied LocalExecReceiptEvidence. Terminal/unknown diagnostics do not require the original execution window to remain live; the current runtime certificate and structural receipt remain verified. Receipt fields never select the expected window. Receipts attest local trusted target observations; they do not prove remote writes or themselves authorize etcd End.

Renew uses fixed purpose/domain `operation_exec_renew`, original accepted context/digests and fresh bounded interval<=30seconds. Backend requires same original capability and current fences/clock/issuer/lease and successful current operation renewal where needed. Target only extends an in-memory existing accepted/live command and persists latest maximum accepted deadline before ACK. No absent/history/reopened/terminal command can renew. Same renewal replay is idempotent without widening its signed interval; different command/digest/epoch/issuer fails. Terminal prevents further extension. Losing API transport stops new renewal; target authority expires and real cleanup follows, rather than equating connection/context loss with terminal.

## Actual PID1 and monitor execution

New controlrunner Supervisor is initialized only with an original constructor-owned actual current PID1 KernelBoundary, protected user/security configuration, pinned clock/trust, bounded registry and a protected journal directory. KernelBoundary gains a private constructor self seal checked by ValidateCurrent before locks/kernel IO; zero/copied boundaries cannot satisfy this consumer and Snapshot remains diagnostic only. Existing exact kernel-state validation/drop semantics remain unchanged. It generates its own fresh BootID/runtime key, publishes only copied Birth diagnostics, and creates the current journal and runtime TLS credential only after successful Root activation; no caller-supplied BootID/key/old journal can reconstruct this Supervisor. It starts no user program until activation and durable accepted one-use registration. User payload enters only authenticated framed control delivery. It launches its own immutable binary in fixed `monitor` mode with bounded framed request on dedicated pipes; no private key, journal/control socket or signing provider enters that process. Parent uses one registered Cmd.Wait owner for management monitor only. All ExtraFiles are explicit, CLOEXEC/closed; no caller command/env can switch management mode.

The monitor calls PrepareMonitor/ConfineMonitor before one user spawn, drops to exact activated original UID/GID, clears supplementary groups/capabilities and uses explicit file streams. RequiresNetwork=true rejects when the independently activated NetworkAllowed=false. Bare argv0 resolves against signed user PATH and cwd, not parent's management PATH; all other argv bytes/stdin/env/cwd are exact descriptor values. No shell interpolation. TTY=true creates a real PTY/session/controlling terminal with merged stderr and finite stdin EOF; TTY=false uses separate stdout/stderr. No new dependency is needed: existing x/sys/unix provides PTY primitives. Unsupported platforms reject before mutation.

The sole monitor observes exact root raw wait status while accounting for every adopted/clone status (combined4096 bound), then performs actual Drain to ECHILD with fresh<=30s cleanup budget. Cancellation/authority expiry/command timeout drives termination and drain; naturally completed root still requires descendant drain. No Cmd.Wait competes for the user. Missing root status, unsafe identity, monitor death, IO error or inconclusive reader/wait join is unknown; never manufacture exit0 from arbitrary reaped PID. Real streams use bounded frames and joined readers, not journal/global buffers. Monitor authority deadlines use absolute namespace CLOCK_MONOTONIC values derived conservatively from fresh PID1 UTC+1second and measured elapsed, never a resettable relative budget or serialized Go/wall-clock deadline. IPC/start delay cannot extend them; accepted renewals carry only new durably authorized absolute deadlines, bounded by command timeout/activation. Deadline expiry may produce a local_terminal receipt only after attributable root status plus actual successful drain; uncertainty closes gate and triggers PID1 isolation.


Cleanup lifecycle coordination uses origin-sealed `RootLifecycle`, constructed by `NewRootLifecycle(initialDeadlineNS int64) (*RootLifecycle,error)`, plus `(*MonitorBoundary).SuperviseRootWithLifecycle(ctx context.Context, rootPID int, life *RootLifecycle) (RootExitObservation,error)` and `(*RootLifecycle).Renew(ctx context.Context, deadlineNS int64) error`. Prescribed SuperviseRoot remains the same cleanup-only behavior without renewal. This coordination observes only an already completed trusted spawn and never grants Start. Lifecycle binds exactly once to its original sole wait owner/root; zero/copies/unregistered/reused/closed lifecycles reject. At most one queued renewal, bounded caller context<=1second, buffered bounded completion, no detached worker or callback/external IO in the wait owner. Sole owner orders old absolute authority expiry/command cancellation and root terminal/ECHILD observations before queued renewal; it freshly rechecks old expiry/context before installing a nondecreasing bounded absolute deadline and issuing success. After any cleanup/terminal transition no new renewal succeeds. Successful sole-owner response is the renewal linearization point; a later physical root exit or ACK transport transit cannot retroactively undo that accepted transition and ACK is never a continued-liveness promise. Monitor control writer remains bounded/joined, and PID1 serializes durable persist, monitor delivery/ACK and actual execution-state checks before returning success. Lost/canceled/uncertain delivery remains unknown/fail-closed. Actual root death between live observation and ordered response remains a concurrent physical event, never proof of resurrection or permission beyond absolute authority/command/activation caps. Meaningful ordering/race tests force expiry/root status before request rejection and accepted renewal before later termination; native renewal-expiry proves actual cleanup.

Lifecycle readiness observation: `(*RootLifecycle).WaitRegistered(ctx context.Context) error` waits only for the original sole wait owner to bind an already-spawned root. It validates constructor origin before locks, requires a nonnil caller deadline<=1second, rejects cancellation/zero/copies/closed or aborted ownership, starts no worker and grants neither Start nor continued-liveness authority. A private one-shot ready signal closes only at successful sole-owner registration; a simultaneous closed/done observation wins over readiness success, and readiness return rechecks current registered/running/not-closed state and caller context. Monitor starts and registers its sole root worker immediately after actual spawn, waits this bounded readiness before publishing monitorStarted or accepting control renewals, then joins that same worker on every result/error path. Root exit after readiness remains a concurrent physical event governed by terminal-before-renew ordering and unknown/fail-closed handling. Never relax unregistered renewal rejection to hide startup scheduling races. Meaningful tests force registration-before-publication, readiness cancellation/timeout, copied origin and ready-plus-closed outcomes.

Already-completed registration path: a valid very short user may finish before the monitor caller observes lifecycle readiness. Closed/done still forbids a live-readiness success or renewal, but it must not discard an attributable successful result from the original registered sole root worker. Monitor consumes and joins that same bounded worker; only its successful RootExitObservation for the exact actually-spawned root, actual terminal raw wait status and current-sealed successful descendant drain permit reporting historical actual-spawn registration followed by the ordinary local_terminal result. This is the existing terminal path, not a new nonstarted subtype or a live/Start grant. No registration or terminal success follows aborted/unregistered/failed or inconclusive ownership. Keep framing/output owner joins and original absolute cleanup watchdog bounds; readiness loss never starts a second wait/drain budget. Any already-completed indication carried over private monitor IPC is typed/bounded and marks parent execution completing/terminal before exposing a renewal-eligible state; it never revives the lifecycle or bypasses actual result verification. Deterministic closed-before-readiness ordering and a real short-lived valid user must prove this path without sandbox isolation; uncertain results retain unknown/isolation. A physical death after genuine live readiness remains the ordinary concurrent termination case.


TTY input contract: TTY=false preserves the exact binary stdin bytes and pipe EOF. TTY=true writes the signed input bytes to a real controlling PTY using canonical terminal input, with ECHO/ECHONL and OPOST disabled, then terminal VEOF to finish finite input (flush a final partial line before the empty-line EOF). Canonical control characters, line editing and line-length behavior apply; PTY input is not a binary-transparent pipe. Preserve master output until actual child/descendant drain and reader completion, never replace PTY with pipes or close the master merely to simulate input half-close. If the user changes terminal settings, those settings govern subsequent input/EOF interpretation; command/authority deadlines still bound actual cleanup. Native coverage distinguishes nonTTY binary/NUL/stdin EOF, actual TTY descriptors/session/merged stderr, complete/final-partial/empty canonical input EOF with output retained, and control-character behavior. Primary semantics: [termios(3)](https://man7.org/linux/man-pages/man3/termios.3.html) and [pty(7)](https://man7.org/linux/man-pages/man7/pty.7.html).

Idle service boundary: the existing production PID1 main accept path may block passively on the root-protected control listener without periodic wakeups. No idle per-target execution/monitor/refresh actor or etcd client, Lease, timer, ticker, watch or clock RPC is permitted. Connection handlers exist only for actual incoming requests, remain within the original16-connection/five-second handshake-header limits and are stopped/joined on shutdown; bootstrap Hello/activation is bounded and stays closed to user execution. This permits the prescribed server itself, not additional per-idle polling services. Fixed Go runtime threads, socket/FD and memory are actual per-target costs to measure; idle N does not imply zero physical O(N) cost.

## Original capability delivery and binary interface

Backend.DeliverExecEffect(ctx, prepared, destination) validates same backend/original capability/draft, current committed exact effect, original deadline and private fences, establishes pinned mutual TLS to exact original target, then repeats all original fences/time immediately before sending the payload. Destination is a typed exact-target connection/credential binding; its dialer carries only bytes, never a callback receiving payload/ticket/private key. A TLS handshake alone is not authorization. Authenticated StartEnvelope contains expected context derived from the original draft, copied exact request, ticket and issuer evidence. Target compares static fields to activation and dynamic fields to authenticated trusted backend assertion, then verifies ticket/descriptor independently. No public Prepared ticket/descriptor getter or historical delivery constructor.

Start returns an opaque ExecDeliveryHandle after accepted ACK; release cap.mu before streaming/wait/renew. Handle preserves private original origin and target/receipt binding. Query is diagnostic and cannot replay. Failed ACK is delivery-unknown, retaining the command ID for query; no new command ID/retry through history. Deliver retry may send only same original command under fresh original authority and target deduplication.

`sandbox-launcher serve` is actual PID1 entry; `monitor` is private fixed trusted subprocess mode with inherited request/control descriptors; `bridge` has fixed root-only Unix socket and byte-only relay, no user argv or key flags. Serve consumes strictly root-owned protected configuration and authenticated clock socket/public key; missing/unsafe files or source stays closed/refuses startup. Native test mode may supply a clearly identified fixture clock/activation authority; production main has no fixture/env bypass. Images/runtime adapters are wired only in a subsequent reviewed task, preserving distinct Docker network/FUSE and Kubernetes mounter topologies.

Production bootstrap interface: fixed root-protected `/run/sandbox-control/config.json` supplies only pinned roots/binding, independent user/network/contract and authenticated clock socket/public-key configuration; no user environment or arbitrary key/argv/socket flag selects authority. Fixed `/run/sandbox-control/control.sock` may accept bounded plaintext Hello and Root-signed activation installation only while freshly closed, with no user-command acceptance. Bootstrap uses strict uint32-big-endian framing, bounded total messages<=16384bytes, duplicate/unknown/trailing/truncated rejection and original16-connection/five-second request limits. Hello returns copied current constructor-generated Birth diagnostics; independent external Root attestation must bind actual observed runtime UID/current birth/security contract before signing activation. Config or Hello alone cannot supply independent observation. Activation is verified against pinned roots/binding and the live original Birth, then persisted before switching this same protected listener to TLS-only commands. Once activated, plaintext bootstrap cannot downgrade or reopen the gate; uncertain/missing activation stays closed. No file watcher or idle polling service is added.

Public TLS request boundary: exactly one request per TLS connection. Client writes the strict bounded metadata and exact declared binary stdin, then calls TLS CloseWrite. Server requires the completed input EOF before durable acceptance, so extra trailing bytes, truncation, size/purpose/schema violations or missed request deadline cannot start a user. Accepted receipt ACK still precedes bounded output/result streaming. Renewal and diagnostic query use separately authenticated fresh connections; query/duplicate history never grants another spawn. Lost ACK/connection remains unknown and uses the same command identity, not a replacement request. The EOF wait remains within the original five-second handshake/header/input deadline.

Credential comparison seam: add `(*ManagementTLSCredential).MatchesCertificate(certificate []byte) bool` solely to compare the configured immutable custom-certificate bytes with the original Prepared selected issuer; nil/zero/empty credentials or mismatched bytes return false. `Destination.Match` also checks its original exact runtime binding. No key/certificate getter, general signing or effect authority is exposed. Equality proves only configured identity agreement, not root trust, freshness, key possession or delivery permission; actual pinned mutual TLS verification and fresh original etcd/time authorization remain mandatory. This is a focused Task1 interface extension consumed only by Task4, with covering comparison/actual-handshake compatibility tests.
