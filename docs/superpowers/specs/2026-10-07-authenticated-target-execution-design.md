# Authenticated target activation and real execution design

This unit implements the next physical part of the user-approved native etcd migration, on `codex/etcd-state-management` from `feat/workspace-fuse-mount`. The goal remains a complete Redis replacement and bounded work with large existing sandbox count N. The earlier local confinement/drain unit is complete at4c5c356, independently reviewed with complete permanent evidence. This unit must finish with actual PID1/monitor/user execution from an original PreparedExecEffect, not another passive diagnostics milestone. Production Manager, Docker/Kubernetes image wiring, lifecycle/task/remote settlement, scheduler/collector/GC and final Redis removal remain subsequent required phases1–5 work; no deployment or online mixed backend is introduced.

## Chosen architecture and alternatives

Use a root-protected Unix control socket, immutable byte-only relay, and TLS1.3 end-to-end between the original backend and the actual sandbox PID1. The relay owns no API/target private key and executes no user argv. A freshly bootstrapped PID1 creates a nonreused UUID BootID and runtime delegate key; an operator activation authority certifies an independently observed exact runtime UID and this current birth. The target independently pins its birth/key/user/security contract and current authority/issuer/gate. Authenticated delivery from the trusted original backend supplies dynamic operation context, after fresh original etcd fences and time checks; the target checks that context against its independently installed static activation and signed full request.

Rejected alternatives: a root Unix peer plus ticket alone lacks authenticated committed-delivery context; historical etcd records cannot reconstruct original execution authority. Running commands in a sidecar changes user namespaces/cgroups and violates the original execution contract. A general public payload/transport callback would expose Prepared internals and is not introduced.

On monitor failure the target closes admission, retains unknown, stops and joins registered management owners where possible, and terminates its own PID1 with a nonzero exit. Linux terminates remaining processes in that private PID namespace when its init exits; this is conservative whole-runtime isolation, not a business End or remote-write settlement. A future lifecycle worker must observe exact runtime termination and remote settlement independently. Primary reference: [pid_namespaces(7)](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html). Availability costs are loss of this sandbox and original-quota failure; no new namespace/host privilege is requested.

## Trust, birth and activation

The operator, not a user API request or command issuer, holds the root activation signing key. Deployment-pinned ManagementVerifier roots/binding are immutable. PID1 uses BootstrapPID1 and actual ValidateCurrent before publishing its Hello. BirthContext contains BootID, fresh runtime Ed25519 public key, independently configured original user UID/GID, independently bound NetworkAllowed and security ContractDigest. ContractDigest binds immutable image, launcher version, IPC/security/namespace/cgroup/network/mount topology and user identity. Native fixtures derive the image/resource/security assertion from actual Docker inspect; later production attestation must do the same through the exact runtime adapter/current original creation claim. A tag/config-provided UID is not that attestation.

Root-signed TargetActivationClaims include version1, role `target_activation`, root key ID, nonreused ActivationID, TrustBinding, SandboxID, WorkspaceHash, Generation, exact RuntimeReference (BootID=current canonical UUID), DataGateEpoch, user UID/GID, NetworkAllowed, ContractDigest, runtime identity certificate digest, selected command issuer certificate digest and UTC NotBefore/NotAfter. Lifetime<=1hour, additionally bounded by both delegate certificates. New wire uses snake_case nested binding `{namespace,authority_id,target,restore_epoch}` and identity `{sandbox_id,workspace_hash,generation,runtime}`; runtime stays `{id,uid,boot_id}`. Private wire DTOs preserve existing public Go types/serialization. Add only strict boolean schema support for NetworkAllowed, without changing existing schemas. Verification authenticates the root claim before using its externally observed runtime tuple, pins the independent local birth/user/network/key/contract, verifies both delegate certificates against the authenticated tuple/current binding/clock and requires independent root/runtime/command keys. It returns opaque TargetActivationEvidence with copied diagnostics; it is not a generic raw execution token.

Activation install is permitted only on the freshly created live journal handle, never a reopened handle. It persists a separately bounded activation file (<=16384bytes, included in byte/file accounting) and exact immutable binding and open gate through the protected journal under its lifetime lock, then marks this live Supervisor active. No user call, unknown historic record or reopened journal can activate. Same activation retry may confirm existing state; different activation/current birth mismatch fails closed. Every boot is fresh: existing state for another boot is never adopted or automatically repaired. Startup with uncertain/missing required state stays closed. Operator recovery/rotation/reopen with fresh task authority remains separately required; this first unit supports one installed activation/selected issuer until close, avoiding a false partial rotation protocol.

## Controlled clock and TLS key custody

Move existing ClockObservation and AuthorityClock definitions into controlprotocol and retain etcd aliases, preserving current provider contracts/tests. Add an authenticated signed-clock IPC client/service: fresh UUID challenge and audience plus TrustBinding on each call; a separately deployment-pinned dedicated Ed25519 clock public key authenticates fixed `authority_clock_observation` domain/purpose, binding, nonce, audience, UTC and uncertainty. Key is independent of operation/activation delegates. Clock wire uses the same new snake_case binding DTO. Client measures entire monotonic call elapsed, rejects uncertainty+elapsed>1s, wrong nonce/binding/key/shape and late context, then returns an observation accounting for elapsed conservatively. Service takes an explicit trusted context-honoring AuthorityClock source; it never invents zero uncertainty/local wall trust. Underlying time synchronization/provisioning is an operator trust contract and a later deployment gate, not certified by a fixture source. Active calls only; bounded connections, closed on stop.

NewManagementTLSCredential copies a delegate private key and its custom signed identity certificate and proves key agreement; no private-key getter exists. Returned TLS configs must expose only an unexported immutable crypto.Signer wrapper, never raw private-key bytes. Its Sign accepts only crypto.Hash(0) and the exact64-space TLS1.3 CertificateVerify padding, role-specific `TLS 1.3, client CertificateVerify\x00` or `TLS 1.3, server CertificateVerify\x00`, and32/48byte transcript hash. Any operation/activation/publication/renew/clock payload signing request rejects; leaf creation uses the private key internally before the restricted signer is exposed. Generated self-signed single Ed25519 leaf carries no separate authority: peer authentication verifies its bounded DER, self-signature, non-CA/digitalSignature/exact role EKU, exact public key from the independently authenticated custom certificate, TLS version/ALPN/no-resumption and fresh certificate interval. Server demands a client certificate; client custom pin verification is complete even where standard CA/hostname verification is disabled. Both roles use VerifyConnection and disable tickets/cache. Client peer runtime tuple is from original trusted state, server peer issuer is from protected activation, never selected by peer leaf or request. Primary reference: [crypto/tls](https://pkg.go.dev/crypto/tls). Existing ExecCommandIssuer signing interface remains unchanged; a new separately configured opaque transport credential must match that exact selected issuer, without extracting a key from the provider.

## Durable acceptance, renewal and result records

Keep version1 unknown history readable. New version2 exec records have states accepted, local_terminal or unknown; full payload/ticket/stdout are never persisted. They retain exact original context/digests/window, latest accepted authority deadline, root/result scalar diagnostics and termination reason. Active journal configuration supplies an independently copied BirthContext, pinned ManagementVerifier and AuthorityClock together; absent all three preserves passive compatibility, partial/typed-nil configuration rejects. Install/accept/renew recheck the installed certificate, activation and evidence time against fresh controlled observations before and after dangerous persistence; late/unknown writes return no new registration or successful ACK and retain uncertainty. Initial acceptance creates a fresh record only while this live activated gate is open and exact expected fields match. Unknown/existing accepted/terminal history is deduplication/query state, never a reconstructed start capability. A retry with exact command/context/digests/window returns its state and cannot spawn again; conflicting bytes fail.

The accepting live Supervisor owns a private one-use start registration; consume it before monitor creation. Failure/uncertain persistence after acceptance stays unknown and closes target, no replay. Signed runtime receipts distinguish accepted, local_terminal and unknown; bind exact runtime/birth/command/operation/digests/epoch, root PID/raw status and local-drain success only where actually observed. Their signature domain differs from publication/start/renew; verification pins externally trusted accepted context/digests, original NotBefore/NotAfter and latest durably accepted authority deadline exactly before yielding opaque copied LocalExecReceiptEvidence. Terminal/unknown diagnostics do not require the original execution window to remain live; the current runtime certificate and structural receipt remain verified. Receipt fields never select the expected window. Receipts attest local trusted target observations; they do not prove remote writes or themselves authorize etcd End.

Renew uses fixed purpose/domain `operation_exec_renew`, original accepted context/digests and fresh bounded interval<=30seconds. Backend requires same original capability and current fences/clock/issuer/lease and successful current operation renewal where needed. Target only extends an in-memory existing accepted/live command and persists latest maximum accepted deadline before ACK. No absent/history/reopened/terminal command can renew. Same renewal replay is idempotent without widening its signed interval; different command/digest/epoch/issuer fails. Terminal prevents further extension. Losing API transport stops new renewal; target authority expires and real cleanup follows, rather than equating connection/context loss with terminal.

## Actual PID1 and monitor execution

New controlrunner Supervisor is initialized only with an original constructor-owned actual current PID1 KernelBoundary, protected user/security configuration, pinned clock/trust, bounded registry and a protected journal directory. It starts no user program until activation and durable accepted one-use registration. User payload enters only authenticated framed control delivery. It launches its own immutable binary in fixed `monitor` mode with bounded framed request on dedicated pipes; no private key, journal/control socket or signing provider enters that process. Parent uses one registered Cmd.Wait owner for management monitor only. All ExtraFiles are explicit, CLOEXEC/closed; no caller command/env can switch management mode.

The monitor calls PrepareMonitor/ConfineMonitor before one user spawn, drops to exact activated original UID/GID, clears supplementary groups/capabilities and uses explicit file streams. Bare argv0 resolves against signed user PATH and cwd, not parent's management PATH; all other argv bytes/stdin/env/cwd are exact descriptor values. No shell interpolation. The sole monitor observes exact root raw wait status while accounting for every adopted/clone status (combined4096 bound), then performs actual Drain to ECHILD with fresh<=30s cleanup budget. Cancellation/authority expiry/command timeout drives termination and drain; naturally completed root still requires descendant drain. No Cmd.Wait competes for the user. Missing root status, unsafe identity, monitor death, IO error or inconclusive reader/wait join is unknown; never manufacture exit0 from arbitrary reaped PID. Real streams use bounded frames and joined readers, not journal/global buffers. Monitor authority deadlines use absolute namespace CLOCK_MONOTONIC values derived conservatively from fresh PID1 UTC+1second and measured elapsed, never a resettable relative budget or serialized Go/wall-clock deadline. IPC/start delay cannot extend them; accepted renewals carry only new durably authorized absolute deadlines, bounded by command timeout/activation. Deadline expiry may produce a local_terminal receipt only after attributable root status plus actual successful drain; uncertainty closes gate and triggers PID1 isolation.
