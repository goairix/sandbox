# Exact one-request Kubernetes runtime cleanup client

这是已批准安全释放方案中具体客户端的独立并行交付，不增加业务范围。完整权威合同仍是 `2026-10-16-local-runtime-safe-release-design.md` 第13–20/26–28条；本文锁定文件职责和独立验收。接口/七值enum已在6160c36提交，Backend作者继续etcd authority/termination/release，不能重复编写本客户端。

1. 保持现有 `TaskRuntimeCleanupOptions`、`TaskRuntimeCleanupBinding`、七值 `TaskRuntimeCleanupStep`、`TaskRuntimeCleanupObservation` 公共字段。实现 `NewTaskRuntimeCleanupClient(TaskRuntimeCleanupOptions)(*TaskRuntimeCleanupClient,error)`、`Close()error`、`Prepare(context.Context,TaskRuntimeCleanupBinding,[]byte)(*PreparedTaskRuntimeCleanup,error)` 和 handle的 `Descriptor()[]byte`、`Observe(context.Context)(TaskRuntimeCleanupObservation,error)`、`Apply(context.Context,TaskRuntimeCleanupStep)(TaskRuntimeCleanupObservation,error)`。零值/复制client或handle拒绝，diagnostics不授予claim/physical/release权限。
Root逐槽接口裁决：另加 `ObserveStep(context.Context,TaskRuntimeCleanupStep)(TaskRuntimeCleanupObservation,error)`，只读固定enum对象，并在原handle私有保留该槽实际UID/RV snapshot。Backend据copied观察写持久intent+新鲜nativeguard后才Apply；Apply消费同槽未消费snapshot，重查漂移即拒绝，实际mutation必须使用原snapshot UID/RV，不能重选新RV绕开已持久intent。自己的已知RV变化也要在下一step ObserveStep→intent前观测。只读ObserveStep不得清除consumed/unknown或恢复重发。原Observe仅Pod诊断，每槽Terminal只代表该对象，absence/disabled/dedup不是no-send或physical/all-artifactsproof。现有公共字段/七enum不变。descriptor永久pin name/UID/profile/binding，历史RV仅诊断；合法RV刷新只允许发生在ObserveStep前并且所有原profile/ownership重新匹配。

Step诊断的消费合同：Install以精确Pod的Retained=true确认；DeletePod以Deleting&&Retained确认该API状态，再由Backend求独立physicalproof，不能等待PodAbsent导致finalizer死锁。四policy分别确认Absent；disabled/dedup的空Kind仅skipped，Terminal=false不阻塞不存在的目标。Remove观察Retained=false只代表自己的finalizer已除。Backend最终仍需独立点读PodAbsent和所有配置且去重policyAbsent，以及持久slots complete/skipped+真实proof后才写cleanup-complete。ACK不伪装readback，absent不倒推no-send。

Authority.Namespace必须是真实etcd规范根路径（绝对路径/尾斜杠/至少三合法segments/总长≤512/末scope和cell≤128），不是API Namespace或≤128单段字符串；fixture也必须用真实根路径。TaskID规范UUID。保持provider独立不importetcd、不修改旧controlprotocol validator；增加真实512/513与非法segments/归属用例，不能以单段fixture掩盖真实Backend无法Prepare的问题。

RestoreEpoch沿用原ASCII segment≤128合同，合法非UUID如restore不能被拒绝；AuthorityID/Target沿用≤128字节、有效UTF8且无control的opaque值，不当作路径segments或拼API路径。它们必须与原binding精确相等。UUID仅用于本方案要求的TaskID/creation/node/boot/实际Kubernetes UID等字段，不把所有身份字符串统一强制UUID。新增finite身份codec用例验证真实来源输入，不能改变旧协议来适配新消费者错误。
