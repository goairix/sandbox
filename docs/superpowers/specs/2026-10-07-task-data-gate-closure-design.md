# Task-authenticated durable data-gate closure

This is the next required decomposition of the approved `2026-10-06-etcd-state-management-design.md`. Branch `codex/etcd-state-management`, predecessor accepted source/evidence HEAD `9a7e37d`. Scope: one-way task-authenticated CloseData, durable attribution, authenticated historical query, and original-claim-fenced delivery. Production cutover, CloseAll, dual drain, termination, remote settlement and owner release remain mandatory downstream work.

## Intent and invariants

Destroy already atomically closes etcd admission and creates permanent task metadata. This unit closes the SAME runtime data-gate epoch before a future worker drains operations. An authenticated close receipt means only that the exact incarnation durably stopped accepting new data operations. Commands accepted before close may start or finish after close; the active registry and sole-wait owner must remain available for later drain. Cancellation, missing tokens, local process exit and this close receipt never prove remote settlement or authorize owner release.

No per-idle-sandbox Lease, clock refresh, goroutine, ticker, Watch or new dependency. Keep native limits 64 operations/64KiB record/256KiB mutation and target journal default 256MiB, warning70%, refuse new dangerous work85%, hard65536 content files. No quota increase, production wiring, Redis deletion or changes to unrelated Sentinel document in this unit.

## Typed signature protocol

Create `TaskCloseDataContext` with snake_case JSON for every field: Namespace,AuthorityID,Target,RestoreEpoch,IssuerCertificateID,IssuerCertificateDigest,CommandID,TaskID,TaskDigest,ClaimID,WorkerID,SandboxID,WorkspaceHash strings; Generation,DataGateEpoch,ControlRevision,ClaimCreateRevision,LeaseID int64; Runtime RuntimeReference. Context is comparable and contains no timestamp or business ExpiresAt. ControlRevision is the destroying control's original task birth revision, NOT TaskRecord.ControlRevision (the prior active revision). ClaimCreateRevision must exceed ControlRevision. IDs use existing canonical UUID/ID validators, hashes lowercase SHA256, all scalar authority revisions/epochs/Lease positive. TaskDigest is SHA256 of canonical strict permanent TaskRecord. Runtime exact ID/UID/Boot and installed restore are pinned independently from ticket contents.

`TaskCloseDataTicketClaims{Version uint32; Purpose string; Context TaskCloseDataContext; NotBefore,NotAfter time.Time}` has version1 and purpose `task_close_data`. Sign domain is actual-NUL `sandbox-task-close-data-ticket:v1\x00`; wire maximum4096 bytes. Ed25519 delegate must match verified CommandIssuerIdentity, certificate ID/digest, exact Namespace/AuthorityID/Target/RestoreEpoch and interval. Signer strictly decodes copied issuer evidence to check the binding as well as opaque identity consistency; no old exec protocol change. Reuse pinned ManagementVerifier, existing strict recursive wire codec, non-null exact schemas, canonical UTC, no unknown/duplicate/omitted/trailing/nonUTF8/isolated-surrogate input and copied evidence. Interval is positive and at most30seconds; current verification requires now-1s >= NotBefore and now+1s < NotAfter. No business-expiry cutoff: an expired sandbox still requires cleanup. Pure signature verification grants no live claim, committed intent, TLS peer or runtime authority.

Public APIs: `SignTaskCloseDataTicket(ed25519.PrivateKey,CommandIssuerIdentity,TaskCloseDataTicketClaims)([]byte,error)`; `(*ManagementVerifier).VerifyTaskCloseDataTicket(ticket,issuer []byte,expected TaskCloseDataContext,now time.Time)(TaskCloseDataEvidence,error)`. Opaque evidence getters Wire/Digest/Context/NotBefore/NotAfter; every returned wire is owned, zero evidence on any error. Signer does not derive metadata or change caller context/time.

`TaskDataClosedReceiptClaims{Version uint32; State string; Context TaskCloseDataContext; TicketDigest string; NotBefore,NotAfter time.Time}` has version1/state `data_closed`, same original ticket interval, domain `sandbox-task-data-closed-receipt:v1\x00`, maximum8192 bytes. Public `SignTaskDataClosedReceipt(ed25519.PrivateKey,TaskDataClosedReceiptClaims)([]byte,error)` and `(*ManagementVerifier).VerifyTaskDataClosedReceipt(wire,runtimeCertificate []byte,expected TaskCloseDataContext,ticketDigest string,notBefore,notAfter,now time.Time)(TaskDataClosedReceiptEvidence,error)`. Evidence getters Wire/Context/TicketDigest/NotBefore/NotAfter/State. Verify fresh pinned runtime receipt certificate against exact RuntimeIdentityContext and now, then exact original attribution/window within runtime certificate, strict signature/domain/schema. Historical receipt may be queried after ticket expiry while the runtime certificate is still freshly valid; this grants no command capability. No drain/terminal/remote/owner-release booleans in this receipt.

## Permanent etcd authorization

Options gains optional `TaskIssuer TaskCommandIssuer`, an immutable concurrent-safe context-honoring operator dependency exposing Certificate(ctx) and SignCloseData(ctx,certificateDigest,claims). Construction does not call providers/clock, requires publication trust/clock if configured, rejects typed nil. A separate typed signing purpose does not allow a different TLS peer: delivery must match the exact issuer certificate installed by target activation. Share the existing immutable issuer registration protocol via a narrow private helper; preserve RegisterExecIssuer/LoadExecIssuer behavior.

`PrepareTaskCloseData(ctx,*TaskClaim)(PrepareTaskCloseDataResult,error)` owns one private draft per original claim, fixed command UUID and monotonic deadline captured before signing and NEVER widened by RenewTaskClaim. Context is derived from retained original fences/decoded task, not caller IDs or diagnostic TaskReference. Check original complete task fences before signing, native commit and delivery, with local irreversible loss and parent cancellation. Controlled time uses existing <=1second elapsed+uncertainty contract. Bound interval by original monotonic deadline mapped conservatively to UTC, <=30seconds and issuer certificate; target and delivery additionally require the original interval to fit the exact runtime certificate. Do not cap by TaskRecord.ExpiresAt.

Fixed permanent key `p/<partition>/tasks/<taskID>/close-data` stores strict version1 `TaskCloseDataRecord{Task TaskRecord; Claim TaskClaimReference; Context TaskCloseDataContext; TicketDigest,IssuerCertificateID,IssuerCertificateDigest string; IssuerRevision int64; Ticket json.RawMessage; Attempt StageAttemptLocator}`. Maximum16384bytes. The enclosing version is an explicit uint32 field. Record stores stage locator rather than self-referential mutation digest. One immutable intent per task; no replacement, age GC or unconditional retry/new command over an unresolved intent. Stage ID `task_close_data`, RequestID original ClaimID, attempt canonical UUID. Native Stage outcome remains distinct from external target outcome.

Full fixed comparison shape: 8 permanent original task fences ×4 =32; claim and guard ×4 =8; issuer value/Mod/Lease0=3; close-intent absence=1; one write=1; existing Stage reserve14: conservative charge59/64. This charge is distinct from the unchanged CommitStage serialized wire:52 comparisons (44 business +4 base +4 guard/receipt),2 success writes and4 Else reads,58 nodes. Assert both actual wire shape and conservative pre-Grant budget; no weaker fencing to fit. Use original Commit/ResolveStage/ReleaseStage and retain exact original attempt when Begin/commit replies are lost. Release diagnostics separate from primary errors. Known committed metadata may have no Prepared after postcommit loss.

Opaque PreparedTaskCloseData origin/self-bound to Backend/TaskClaim/private draft, no public ticket accessor. Result carries Outcome, TaskCloseDataReference, Prepared, GuardCleanupError. `LoadTaskCloseData(ctx context.Context,task TaskReference)(*TaskCloseDataEntry,error)` discovers copied structural history at the fixed task close key, then rereads exact intent+original stage receipt in one identity-fenced point snapshot (permanent immutable common revision), never permission. Entry contains Reference TaskCloseDataReference, Record *TaskCloseDataRecord, Revision int64 and Outcome Outcome. Its diagnostic full StageReference derives the digest from the strictly validated original committed stage receipt; command/claim/task/locator must agree throughout. Missing intent is nil snapshot only, never undispatched/aborted proof; an intent plus absent/aborted/malformed receipt is corruption/unknown, not a partial entry. Discovery does not authorize commit or dispatch. Query from a historical intent is read-only; old or fresh claim cannot adopt the original prepared capability. A different claimant seeing an existing intent must reconcile its original receipt; it cannot overwrite or redispatch blindly. Unknown/aborted stages never generate automatic new effect attempts.

## Runtime persistence and closure

One fixed `data-close.json` per exact installed data-gate epoch. Strict <=8192-byte record contains Version1, State (`pending`/`data_closed`), original full TaskCloseDataContext, TicketDigest, NotBefore,NotAfter. No ticket/payload retained. A live fresh journal verifies installed activation identity/birth and exact issuer certificate, current issuer/runtime certificate and fresh ticket; cleanup does not require the old activation/business window to remain valid. Gate epoch never changes or reopens here.

Under journal mutex: authenticate/preflight peak bytes and files for pending plus gate-replacement and terminal-replacement temporaries (at most two additional content files, with actual encoded lengths) -> persist pending attribution (file fsync/rename/dir fsync) -> persist same-epoch closed gate -> reauthenticate live ticket/dependencies -> persist data_closed attribution -> reauthenticate once more -> return copied closed record. Any uncertain write/clock/cancel poisons accounting and keeps local admission closed, no receipt. Pending is never a closed proof. Identical retry uses the same command/context/digest/window; different command, claim or bytes conflicts and cannot overwrite the first record. Exact historical lookup may return pending or terminal structural diagnostics after ticket expiry without performing an effect. Readable data_closed bytes after a failed terminal directory-fsync are not durable proof: Lookup is not a capability. The transport signer must reject poisoned/accounting-unknown or cold journal history even if the record state says data_closed; only clean live installed journal state can supply a close receipt. Cold Open always stays closed and diagnostics-only; never reconstructs fresh activation or capability.

Extend fixed root scan/accounting for `data-close.json` and `.data-close.<UUID>.tmp`, matching identity/gate; validate all original bytes, preserve uncertain temporaries, count all bytes/files, no map/scan per query or destructive repair. Existing gate/activation/exec formats retain canonical bytes. Capacity refusal of dangerous work never reports close success; query remains available within fixed read limits.

APIs `(*Journal).CloseData(ctx,e TaskCloseDataEvidence)(*TaskDataCloseRecord,error)` and `LookupDataClose(ctx,expected TaskCloseDataContext,ticketDigest string)(*TaskDataCloseRecord,error)`; metadata-only arguments cannot authorize a write. On unsupported platforms fail closed like existing journal APIs.

## Transport and delivery

Extend bounded request framing with separately typed task-close context, fixed purposes `task_close_data` and `task_close_data_query`, no execution metadata/stdin. Preserve existing exec wire serialization (separate task DTO/dispatch, not added mandatory fields to old envelopes), EOF validation,16-connection/5second handlers, exact activated mTLS peer and original connection ownership. Query binds exact command/context/ticket digest and returns only original retained terminal receipt from a clean live installed journal; poisoned, accounting-unknown, cold, absent, pending or error is unknown. No automatic retry of a side-effect send.

Supervisor close holds the same admission mutex as accept, sets admission=false before persistence, checks exact installed tuple/issuer, invokes Journal.CloseData, then signs only the durably returned data_closed record with the exact runtime delegate. Post-write loss/timeout may leave durable history but returns unknown. Do not terminate/replace monitors, erase active executions or mark them End. Separate exact-identity query admission from start/renew admission: exec_query remains available after successful data closure, while exec_start and exec_renew refuse. Process/transport Close, failurePending or missing activation still reject query. Query borrows existing lifetime ownership and preserves existing confirmed receipt semantics: a still-active command may remain unknown after closure until its local_terminal record is available; do not sign a new accepted confirmation while admission is closed or monitor renewal ACK is uncertain. Terminal history remains queryable; no synthetic terminal.

Backend delivery rechecks original prepared capability/fences/intent/ticket/deadline before connection, after handshake and before write; verifies exact independently configured Destination runtime birth certificate and exact activated issuer mTLS identity, never caller-selected trust. Fixed one-shot send, signed closed receipt verification against original runtime/context/digest/window. Delivery failure preserves intent and unknown, does not End/revoke owner/delete anything. Historical query is diagnostic and may reconcile a receipt after the task claim expires; it cannot send close or revive authority.
