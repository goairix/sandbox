# Atomic due discovery and worker expiry admission

This is the next necessary part of the approved `2026-10-06-etcd-state-management-design.md`, following accepted worker control f95d100f26ba6ba81f38ed2289090f36f0ca86f1. It does not reopen that Task or require renewed user approval.

## Outcome

New production enrolled publications atomically create a partition/time ordered, permanent expiry candidate with their authoritative active control. An original worker partition and shared Range budget can read only overdue plus the next 60 seconds using bounded pages at one fixed revision. A candidate never grants authority: expiry task admission must re-read and atomically fence the exact current active control, original worker/partition/rate share and original trusted business clock. It creates only the existing metadata destroy task; physical drain/cleanup remains the separate existing task protocol.

## Binding constraints

- Preserve all existing publication authority comparisons, 64 total native request nodes, 256 KiB request/response ceiling and original result arbitration. Never add a loose post-publication index write, weaken a fence, or reinterpret an empty comparison-only transaction as fresh evidence.
- Current enrolled publication is full: 54 compares + 9 success writes + 1 compact Else read. The Else read is not used as identity evidence and is followed by a separate base-fenced read-bearing arbitration. An explicit new closed publication protocol may replace that redundant Else with an empty strictly validated branch to atomically add the index. Preflight must account for all branches and preserve old persisted publication/attempt replay; choose and freeze version compatibility before implementation. Do not silently mutate accepted v2 wire semantics.
- Index is a derived, strictly canonical candidate, not ownership or absence proof. Exact partition/expiry/sandbox/generation/intent identity must prevent collisions and stale candidates must be rejected by current authoritative control. No cached reference can reconstruct worker or task authority.
- No all-sandbox scan, per-sandbox lease/watch/goroutine, full far-future heap, or automatic default enablement. A bounded page uses conservative maximum key/value/envelope size before issuing Range (not only count), at most 256 records and 256 KiB actual response. Charge the original Range share before the actual RPC; no refund on unknown. Fixed revision cursor binds original worker/partition/window and cannot be adopted by a replacement session. Compaction/identity loss/malformed response invalidates the view.
- Expiry admission consumes original claim tokens and must include original worker/profile/session/partition/claim-share fences in the actual metadata mutation, not a preceding permission check. Existing generic Stage capacity is unchanged; if exact safe composition does not fit, use a separately closed domain with fully accounted protocol rather than raising the limit. Unknown outcomes retain the original attempt and cannot release owner/quota or authorize physical cleanup.
- The exact five-key destroy bundle permits44 business comparisons (including originalworker16 and exactdue4), six business writes including deletion of that exact due candidate, plus14 reserved protocol nodes=64. Successful automatic admission must atomically consume its candidate while writing the permanent existing task evidence; failed/unknown outcomes must never trigger a separate index deletion. This prevents repeated scans of already admitted expiry work as retained history grows. Manual/stale candidate GC remains separate.
- Actual task hard concurrency 32 is not implemented by this metadata transition and may not be inferred from the leased shares. Existing mounted execution, dirty/task discovery, fixed-revision Watch/cache, periodic audit, production worker loop, capacity/deployment/Redis removal remain explicit subsequent work.
- Clock anomaly must prevent automatic premature destruction; use the existing trusted clock bound and expiry semantics, never a worker supplied unchecked timestamp as authorization. Index reads are discovery only.
- Root exclusively executes Go/Git/Docker/gofmt and commits verified coherent slices; all edits use apply_patch. No unrelated Sentinel document, old closed OWN/pairs/artifacts, or accepted old native matrix replay.

Host/race and Linux vet cover changed actual owners and named direct regressions. One new finite real three-member fixture verifies the complete publish→index→bounded page→expired metadata-task chain plus competition/failed original fences; it is not a capacity claim. One fresh author and one fresh whole-Task reviewer, same pair for scoped fixes. Exact APIs, key/value/version/budget accounting and test slices freeze in the read-only preflight.
