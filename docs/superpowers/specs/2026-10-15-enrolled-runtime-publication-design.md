# Enrolled Runtime Publication Design

2026-10-15. Refinement of the approved master; prepared against the actual interfaces at `6b0f09d`, with observer commits through `4ce4394` interleaved. Physical observer acceptance is a dependency for final integration acceptance, not a reason to repeat its implementation. This document is design, not test evidence.
Applies approved master `docs/superpowers/specs/2026-10-06-etcd-state-management-design.md`, node-observer physical spec and local-finalization verification report. Existing final-sync pins and accepted limitations remain unchanged.
Execute the companion plan as one complete Task, with coherent verified internal commits and one fresh Task review.

## Decisions and scope

1. Deliver actual PID1 Supervisor enrollment before activation/admission, a separate strict-v2 ready proof, guarded enrolled publication, and cold immutable lookup. Keep legacy profile behavior and validators unchanged.
2. Select explicit immutable operator configuration at construction, bound to the root-certified approved birth ContractDigest. Neither caller activation fields nor a per-request Boolean select/downgrade profile.
3. No launcher/main, ordinary Kubernetes deployment, observer producer, termination composer, provider cleanup, owner release, Redis switch or production-complete claim. Existing nodeobserver command belongs to its producer author.
4. Minimum actual end-to-end profile is Kubernetes plain workspace/no mount. Supervisor has no existing publication-ready producer and no trustworthy FUSE mount observation input. Do not manufacture mount success from a caller Boolean. FUSE concrete enrolled signing remains a later integration; reject it in this profile.
5. Alternatives rejected: append pins to shared Stage (over budget); omit Stage guard (changes unknown-result protocol); export key/sign callback (bypasses live Supervisor); reinterpret PodSpec as birth ContractDigest (different authority).

## Concrete APIs and immutable profile

`controlrunner.NewEnrolledSupervisor(o SupervisorOptions, enrollment NodeEnrollmentOptions) (*Supervisor,error)` creates the actual Supervisor with an immutable private enrolled profile; plain `NewSupervisor` remains legacy.
`NodeEnrollmentOptions { SocketPath string; NodeUID string; NodeBootID string }`: root-owned absolute UDS path, canonical nonzero UUIDs, copied and validated before creating the Supervisor. Actual connection uses net.Dialer.DialContext("unix", path); no supplied connection/signer callback.
Existing `Supervisor.Activate(ctx,e)` dispatches internally by the constructor profile. Existing bootstrap `activate` necessarily takes the same enrolled path. It cannot bypass pending enrollment.
`Supervisor.Enrollment() (controlprotocol.EnrolledRuntimeEvidence,error)` returns copied diagnostics only after completion; no capability constructor or exported mutable registration.
`Supervisor.EnrolledPublicationProof(ctx context.Context, certificate []byte, claim controlprotocol.ClaimReference) ([]byte,error)` signs a new fixed-domain proof only while the same original enrollment, activation, journal and admission are valid. It freshly verifies the publication certificate against the installed identity, birth public key and supplied claim attribution; certificate workspace mode must be plain. Fixed ready fields: gate=open, mount_attempt=0, mount_operation_id=""; finite validity as existing publication clock policy. Never call old SignReadyReceipt.
`etcd.Options.EnrolledPublication *EnrolledPublicationOptions`, with `EnrolledPublicationOptions { ContractDigest string; MaxActive uint32 }`, clones immutable configuration and constructs its management verifier from existing PublicationTrust/binding/roots. This profile requires PublicationTrust and exact approved contract digest.
`Backend.PublishRuntimeEnrolled(ctx context.Context,c *CreationClaim,proof []byte,enrollment controlprotocol.EnrolledRuntimeEvidence) (RuntimeEnrolledPublishResult,error)` requires enrolled profile and an original live claim belonging to this Backend.
`Backend.LoadRuntimePublicationEnrolled(ctx context.Context,w WorkspaceIdentity,intent string) (*RuntimeEnrolledPublicationEntry,error)` performs historical validation; returned result cannot execute, republish or release anything.
`Backend.ReadRuntimeEnrolledPublicationAttempt(ctx context.Context,ref StageReference) (Outcome,error)` is read-only arbitration of this exact attempt; absent remains Unknown. No reconstructed Stage capability.
On an enrolled Backend old PublishRuntime refuses before RPC. On legacy Backend the new API refuses. More importantly, the new proof signature/schema is rejected by old PublishRuntime on ANY Backend, so routing to the old API cannot turn enrolled pending state into active metadata. Mixed-version deployment remains outside this unit.

## Supervisor pending owner and actual joins

Add one private `supervisorEnrollmentAttempt` pointer, not a registry: activation digest, context/cancel, done channel, original socket/session, terminal result/error; at most one attempt per Supervisor boot. Different activation refuses; concurrent identical callers get pending or wait outside s.mu.
Before any clock, socket or journal IO: acquire s.mu briefly, reject closed/failed/failurePending/closeStarted, reserve pending owner, leave admission=false, release s.mu. All subsequent work belongs to that original owner.
Verify activation against actual s.birth, create finite five-second context, dial original UDS, publish socket ownership under s.mu before OpenNodeEnrollment. If closure won, close it and return without signing.
OpenNodeEnrollment sends exact activation/runtime-identity/issuer wires. Authenticate challenge observer certificate with expected configured NodeUID+NodeBootID; require exact activation runtime and request digest. The transport checks digest; the Supervisor checks root/node/incarnation before signing.
Under short s.mu section recheck original pending pointer/closure and sign ONLY NodeEnrollmentChallengeSigningBytes with genuine s.key. Never hold s.mu over Enroll, clock, fsync or join. No private-key copy escapes the owner.
Verify returned receipt against challenge certificate, activation digest and exact runtime/sandbox/workspace/generation. EnrollmentDigest and ObservedAt are signed observer outputs, not caller authority. CreationIntentID remains a signed observed hint until Backend ties it to the exact claim+publication certificate.
Only after observer's durable ACK, verified receipt and successful closed-journal InstallActivation may owner install activation/credential/TLS and set admission=true under s.mu, rechecking all closure flags. The activation/journal owner also stays outside s.mu during IO; ownership transfers once at final install.
If failure occurs, keep admission closed and mark this boot's enrolled activation failed; do not automatically redial/re-enroll or create a second pending owner. Successful repeated Activate of identical evidence is read-only/idempotent; it never reopens a subsequently closed gate.
Close seals closeStarted immediately; stopExecutions marks closed/admission=false, captures pending owner, cancels and closes its exact socket outside s.mu, then waits for original done before existing journal/execution teardown. Session.Close and context.AfterFunc joins complete before done closes.
Uninstalled local journal/credential resources are disposed by pending owner before done. Installed journal is disposed only by destroyResources. destroyResources clears s.key only AFTER enrollment done and all transport borrowers joined. Existing independent 31-second Close isolation deadline remains armed during every wait; cancellation alone never counts as join.
CloseAdmission must mark pending activation permanently closed (a private seal/epoch), so a late enrollment ACK cannot reopen it. Test both Close and CloseAdmission crossing durable ACK and journal installation.

Verification split: the actual observer integration pauses its second provider GET to prove pending enrollment/ACK-before-admission, then resumes the genuine durable observer ACK, Supervisor ready, publication and user execution. Exact delayed-reply/Close/CloseAdmission scheduling uses fixed signed wire on a real Supervisor-owned UDS unit peer and proves only local owner/admission/key lifetime. It is not physical observation evidence or a claimed actual post-fsync/pre-write pause. No UDS proxy, producer success hook or frozen-producer modification is permitted. Producer's journal-fsync-before-reply source order is reviewed independently.

The management TLS credential owns the sole copied TLS private key. Its nil-safe idempotent `Close() error` serializes with bounded key access, seals signing, and clears that key. Management TLS leaf signers reference the credential through a private locked signer; they never copy private bytes. Existing node-observer `tlsOnlySigner` stays unchanged. Supervisor disposes uninstalled credentials and closes the installed credential only after enrollment/signing/transport owners actually join, then clears its original key.

## Authentication bridge and v2 wire

New `controlprotocol/enrolled_runtime_publication.go` owns `EnrolledRuntimeEvidence { Request NodeEnrollmentRequest; ObserverCertificate []byte; Receipt []byte }` and strict codecs/verification. These are untrusted input/copies, never process authority.
Use new purpose/domain `runtime_ready_enrolled:v2` and new closed v2 claims: all original ReadyReceiptClaims plus EnrollmentDigest, ObserverCertificateDigest and ActivationDigest. Complete publication proof retains original creation-bound publication certificate; total proof cap 8192. Old schemas/signature domains stay unchanged.
Backend verifies original publication certificate using preparationCertificateContext(dispatch): full namespace/authority/target/restore/IntentID/sandbox/workspace/generation/operation/payload/snapshot/expiry. The opaque original CreationClaim supplies the exact claim ID/revision/Lease; annotation never supplies creation authority.
Also VerifyNodeEnrollmentRequest authenticates root activation + runtime identity + issuer certificate. Require identical runtime ID/UID/BootID, sandbox/workspace/generation, data gate epoch, approved birth ContractDigest, and exact public key between management runtime identity certificate and publication certificate. Add `ManagementVerifier.VerifyEnrolledPublicationCertificate(wire []byte, activation TargetActivationEvidence, now time.Time) (CertificateEvidence,error)` and copied `CertificateEvidence.PublicKey()` for the Supervisor's independently root-verified bridge; Backend additionally uses its exact preparation context. Never parse unauthenticated fields into authority.
Verify receipt signature/root observer certificate, exact node UID/boot, activation digest, runtime identity and receipt.CreationIntentID == actual c.reference.IntentID == authenticated publication certificate IntentID. Verify v2 ready signature with that SAME runtime public key and bind all three enrollment digests.
Publication uses fresh controlled time and existing proof expiry checks immediately before commit. Cold lookup verifies all signatures at their retained signed observation times, without requiring business/certificate validity today; it grants no current authority. Receipt ObservedAt must fit activation, runtime/issuer and observer certificate intervals; ready time must not precede enrollment.

## Closed records, paths and fixed capacity

Reuse existing intent `runtime-publication` and `publication-proof` key locations, but new dedicated version-2 record types/strict codecs; legacy readers reject v2. Do not broaden RuntimePublicationRecord.Validate or old proof validators.
New keys: `p/<pp>/intents/<intent>/runtime-enrollment` and `p/<pp>/intents/<intent>/runtime-enrollment-activation`. Stage logical ID `runtime_publish_enrolled_v2`; unchanged canonical StageAttemptLocator and receipt key grammar.
Publication v2 journal contains original publication metadata/claim/attempt plus EnrollmentDigest, ObserverCertificateDigest, ActivationDigest, NodeUID, NodeBootID and digests of both enrollment records. Publication proof record uses v2 and exact new proof bytes.

The v2 journal also retains `DispatchAttempt`, `BindingAttempt`, `MountAttemptLocator` as StageAttemptLocator values (`dispatch_attempt`, `binding_attempt`, `mount_attempt_locator`). They copy the original nine pinned preparation KVs' records and only locate fixed receipt keys. Cold lookup rechecks each locator, record, receipt and relation in the same coherent snapshot. Existing `mount_attempt` remains uint8 and is zero in this profile. Include all three locators in actual canonical record and native byte accounting; V1 remains unchanged.
Enrollment record contains version2, exact creation/runtime identity attribution, raw canonical observer certificate and raw canonical receipt. Activation companion contains version2, matching identity, raw canonical activation/runtime-identity/issuer certificates. Use json.RawMessage, not base64 envelopes.
Each entire enrollment record <=8192 bytes, combined <=16384; proof <=8192. Validate actual final canonical sizes before any Grant or mutation, never truncate. Companion is justified because existing independent caps permit observer certificate2048 + receipt4096 + management runtime4096 + issuer4096 + activation16384; one8192 record cannot preserve the authenticating material. V2 deliberately requires the actual activation companion to fit8192; larger otherwise-valid legacy evidence refuses early.
Original creation publication certificate remains in already pinned runtime-certificate record and publication proof; do not duplicate it in enrollment. Cold validation loads it in the coherent history set and cross-checks exact bytes/digest.
All newly written immutable records and receipt have Version1 at etcd level, CreateRevision=ModRevision, Lease0 and the SAME commit revision. Duplicate/missing/unknown/null/noncanonical fields, wrong key/attempt/digest/revision/node/claim or partially present group refuse.

## Stage protocol and exact native budget

Source facts: creationClaimComparisons returns24 (six permanent records times Mod/Value/Lease=18, claim+claim guard times Value/Lease/Create=6). Preparation pins9 immutable KVs times Mod/Lease=18: dispatch/payload/dispatch receipt3; binding/cert/runtime index/bind receipt4; mount/mount receipt2.
Old shared mutation costs24+18+2 absent+6 writes+14 reserved=64. It cannot accommodate enrollment. Keep shared prepareMutation, commitPreparation, CommitStage and old API unchanged.
Implement narrow private enrolled Stage owner using the same fresh locator, 30-second dedicated Lease, guard Value/Lease/CreateRevision, committed stage receipt and cleanup semantics. Its own fixed-domain validation/copy/digest and native preflight replace generic prepareMutation for this path ONLY: beginStageWithLocator invokes the generic14-node reservation and therefore cannot be reused unchanged. No generic custom mutation API.
Preflight all native messages before Grant using maximum native int64/uint64 revision/Lease/header sizes and key root max512. Once Grant is validated, preflight concrete guard again before sending. Unknown Grant/guard never yields a commit capability; return original reference and separately report cleanup failure.
Guard creation:4 base+2 absence comparisons, success1 guard Put, failure2 identity/restore Gets =>9 nodes. All native response/header/put shapes checked.
Commit:4 base+24 claim+18 history+4 absent business records(journal,proof,enrollment,activation companion)+3 original guard comparisons+1 absent receipt=54 compares; success9 Puts(owner/control/request/intent/journal/proof/enrollment/companion/receipt); failure1 exact receipt Get =>64 nodes.
This counts BOTH branches, preserving every current and historical pin. No nested transaction, no removed index/history pin, no prefix discovery. The rejected one-record variant would be62 nodes; two-record bound is exactly64.
Receipt-only failure needs its own exact one-Range envelope validator; never feed it to stageEvidencePoints, which requires identity/restore first. Then arbitrate with separate fixed read-only Txn comparing base identity/restore and reading identity,restore,receipt,guard in both branches (12 nodes). Validate cluster/header, current identity/restore and exact immutable receipt/guard. Existing committed receipt wins only after these checks; absent with live guard stays Unknown/conflict; absent with proven vanished original guard is fenced-not-committed but exposes OutcomeUnknown, never an invented aborted receipt. OutcomeAborted requires actual valid aborted receipt from existing explicit resolver.
Request, success response and failure response EACH <=262144 bytes, each native protobuf Size measured with conservative complete Range KV/header bounds; every transaction <=64 nodes, every key<=1024, namespace root<=512. Fixed record caps included in response estimates. All reads have finite contexts and bounded point key sets.
Store one private frozen enrolled attempt on original CreationClaim before first Grant; same input after any send returns/reads same reference, never grants or resends commit. Different input conflicts. On ACK loss, retries are read-only, including cold reference arbitration; absent remains unknown. Existing explicit Abort/Resolve semantics may fence an attempt, but automatic retry/re-enrollment/new attempt is excluded.
Before commit recheck claim local lifetime, fresh certificate/proof time and Backend closure; server transaction still compares ALL24 exact claim/current pins. Before initial RPC refuse oversized or inconsistent wires. Commit result does not grant runtime effects.

## Cold read and later consumption

First fixed point read locates v2 journal/attempt only; then one base-fenced snapshot loads journal,proof,enrollment,activation companion,publication receipt and the full9 preparation history KVs. Revalidate locators discovered earlier, all same-commit publication records, exact preparation relations and every signature/digest/cross-key binding. No prefix/N-sized discovery.
Absent all publication group is nil, never proof of external abort. Partial group, wrong receipt, mutable/leased history or changed locator refuses. Expired current business state does not erase authentic immutable history.
Returned references/entries are diagnostic copies. Later termination MUST independently fetch this registration and pin its immutable bytes/revisions inside its own reserve transaction; this unit creates no transferable termination authority.

## Binding interface and lifecycle refinements

- `RuntimeEnrolledPublishResult` has `Outcome Outcome; Disposition RuntimePublishDisposition; Reference StageReference; Entry *RuntimeEnrolledPublicationEntry; GuardCleanupError error`. Entry has `Record RuntimeEnrolledPublicationRecord; Proof json.RawMessage; Enrollment controlprotocol.EnrolledRuntimeEvidence; Reference StageReference`; all returned backing is copied.
- Use `NewEnrolledSupervisor` as the sole immutable enrolled-profile constructor; public evidence is untrusted input/copy. Root/operator approval is the exact configured birth ContractDigest, not a self-selected activation field. `NodeEnrollmentOptions` has exactly SocketPath/NodeUID/NodeBootID as above; validate absolute socket path, root ownership and protected socket permissions. Root-certified peer/node identity still must be authenticated.
- Ready validity is at most five seconds, bounded by publication and activation/runtime/issuer/observer certificate intervals. Fresh observed time before signing and immediately before native commit; Backend independently requires the original live CreationClaim. Supplied ClaimReference is attribution only, not a live capability in the Supervisor.
- Supervisor proof signing borrows private key only while registered in its original transport/lifecycle owner; no clock or socket call under s.mu. Close seals new signing before actual joins and key clear. Pending enrollment and installed enrollment are finite disjoint states; CloseAdmission permanently seals both.
- Backend MaxActive is required in1..32 for this profile. A bounded active publication-owner set shares archiveLife.mu and archiveLife.closed with existing Backend.Close admission; no per-live-sandbox registry. Register before first RPC and retain until all actual native/cleanup calls return. Same claim owns one frozen attempt; duplicates wait outside locks or perform readonly arbitration, never allocate another Stage after uncertain send.
- Root-approved narrow close seam: extend taskArchiveBackend with bounded enrolled-publication owners; closeTaskArchiveBackend captures and cancels them in the existing same-mutex admission seal, then joins them before client.Close. No network/IO/join under archiveLife.mu or CreationClaim.mu. Preserve existing archive/store joins and exact idempotent Close result. New lifecycle tests cover Backend.Close during blocked native RPC.
- Immutable lookup's first locator point read is also base-fenced. The subsequent coherent point group rechecks the discovered exact locator and all cross-record relationships. No receipt or history read under failed identity/restore pins may resolve committed.
- One Task includes protocol, Supervisor, etcd and actual integration; plan steps are internal verified commits, not four fresh review gates. Scope still excludes production launcher/manifests and FUSE. No completed predecessor OWN reads, source/test replay or accepted-author reuse.
