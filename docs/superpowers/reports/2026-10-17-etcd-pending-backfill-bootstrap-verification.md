# Pending 历史回填检查点切片验证

本片实现历史回填的持久检查点编码、原 worker 下的实际读取、初始化和读取视图更新。
历史截止修订固定，更新视图保留已确认 frontier；本片不推进 frontier 或标记回填完成。
历史分页、任务认证、终态 pending 移除及自动 actor 接线尚未实现，默认仍使用 Redis。

## 实现边界

检查点为永久、规范 JSON，最大2048字节，绑定 namespace、restore epoch、identity及分区。
通用 Stage 禁止写入其整个键家族及子路径；专用 CAS 复用原会话、分区、Range/Claim
预算、workerCall 和实际返回生命周期，不新增 session、租约、goroutine或公开权限接口。

初始化的截止点和读取视图只能来自原权限约束下的实际当前读取，不能由调用者指定。
之后只允许更新读取视图，截止点、frontier及身份保持不变；complete状态不得重开。
检查点可变，读取校验 Create/Mod/Version/Lease 的一致性；更新精确比较值、Create、Mod
和Lease，拒绝同值改写、删除重建及租约变化。返回对象绑定原 Backend、分区和自身身份。

原生读取25节点、初始化24节点、更新27节点。预检使用实际构造的请求，并覆盖最大
值、整数、响应头及两个响应分支，维持128KiB请求、256KiB响应和64节点限制。
仅在成功原生 Put 响应、修订及调用后权限验证均通过时发布新状态；响应丢失返回未知、
使原会话失效，替代 worker 必须重新读取实际已提交状态，不猜测截止点或已覆盖区间。

较大历史集合未来将从持久 frontier 续接，从而跨越 compaction 窗口；本片只提供该恢复
协议的检查点基础，尚未验证实际历史扫描、compaction续接或大N吞吐。

## 验证

- 原通用 Stage 接受检查点及子路径写入，两个行为 RED 已实际复现；修复后通过。
- 后续缺私有接口的编译 RED 单独保留，没有当作行为断言执行。
- 定向 host 三组/15子例通过1.531s；race 同三组/15子例通过2.602s，无跳过、告警或竞争。
- Linux arm64/CGO0 的 etcd 包 vet通过，无输出。
- 额外覆盖规范编码/最大字段、真实配置的60秒租约和15秒拒绝、原始预算、不复制权限、
  nil/取消/Close、原 worker fence、未退款冲突和 committed ACK丢失后的实际替代会话读取。

host/race/vet分别9036/9041/9127份实际输入，全部17类 Go-list字段、源码/工具前后、归档成员和
当前字节均独立核对；race实际列表和测试命令均带-race。
这些是有界gRPC模型及编码/wire验证，不是真实etcd、自动物理执行或容量验收。
本片没有创建Docker资源，也没有重放此前已验收的物理执行矩阵。
