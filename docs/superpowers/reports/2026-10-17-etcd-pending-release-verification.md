# Pending 签名释放读取切片验证

本片实现共同出生证据到原私有签名释放加载器的受控调用，不写入检查点、execution、
槽位或pending，不代表自动清理、完整回填或生产切换完成。

## 实现与边界

读取只接收同Backend、原分区及原Range份额的私有出生证据，扣费前检查配置、原始身份、
规范Task/intent/link/已提交回执及可选metadata绑定。复制诊断对象不能转移权限。
有效配置必须通过正常构造；没有通过修改活跃Backend绕过Linux归档恢复校验。

单次读取使用原256KiB预算，最多五次RPC：worker前检、原释放记录读取、原终止/provider
读取、原签名历史读取、worker后检；原生节点分别25/10/12/26/25。签名加载器及物理
执行器保持原实现。结果仍须精确匹配初步release版本、Task出生与签名Task摘要；
execution若已有释放摘要，也必须匹配。只返回私有证据，后续事务仍需精确版本比较。

真实会话需TTL60秒，请求r不超过3秒；阶段期限5r+1秒，原租约余量须大于8r+2秒，
预留全部三次续租请求。原owner持有至实际请求返回；取消不会提前释放owner或退款。
沿用已验证的最大字段预检，合法协议记录保守响应总量260480字节；不是服务端CPU、
进程内存或大量已有沙盒性能验收。

原enrolled点读取器仅增加私有网络错误标记，保持原错误文本及errors.Is/As原因链。
即使网络错误被签名加载器与corruption连接，也优先使原会话失效。缺失或坏历史仅在
实际worker后检和owner后检成功后保留健康worker，永远不产生有效释放证明。

## 实际验证

- 编译RED仅包含尚缺的批准接口，未运行断言；原日志保留。
- host五组34叶例通过1.683s；包含释放读取与原出生ownership/wire回归。
- race六组58叶例通过2.975s，并覆盖原出生读取；无跳过或数据竞争。
- 两者各有一条故意取消原RPC产生的预期etcd-client告警，未隐藏或当作无告警。
- Linux arm64/CGO0测试二进制编译及包vet通过，实际9135份输入。
- Linux正常构造配置的模型组13叶例通过0.31s，无跳过；验证独立身份/预算拒绝、
  未签名/删除证据的实际后检、网络/失权/取消失效、Close及Relist实际返回等待。
  使用原gRPC模型、真实归档恢复目录与TLS provider构造；provider和签名issuer调用均为0。

host/race实际9043/9048份输入。全部17类Go-list字段、源码/工具前后、所有归档成员
及当前字节独立核对；race列表和执行命令均带-race。Linux容器限2CPU/768MiB/128PID、
只读根、无外网、临时目录128MiB；退出0、未OOM，容器已删除并核对精确名称清单为空。
模型没有启动真实etcd，没有执行物理清理，也没有签名成功正例；该正例仍需后续自动
消费者的Linux完整组合覆盖，不能把本片拒绝路径测试当作终态验收。
