# 原 worker 自动发现循环实现验证

已实现 `DueWorkerOptions.AutomaticCleanup`：默认 false 保留显式模式；true 在任何启动
RPC 前要求完整物理配置、真实60秒会话及至多3秒请求超时。自动发现、历史回填、签名
终态待办删除和原任务 registry 已接入同一个 actor/session/Range/Claim/Relist 生命周期。
本片尚未完成真实物理配置的自动执行组合或独立进程验收，整个 Task 保持开放。

pending 每页80条固定视图，单个原始续页逐步消费；重复任务前进，registry 满保留
未消费尾部并让出回填机会。历史覆盖复用持久 B 与原原子 P/B 协议；已完成 B 不再扫
历史，已确认 cutoff/frontier 不因视图更新丢失。正常扫完后至少30秒才开始下一轮，
压缩与坏记录不产生全量重试队列。仍要求启用前停止无索引旧 writer，不支持混合旧写入。

Claim 信用在到期、已有清理任务、自动元数据三个等待方间轮转。review 另发现自动
Range 总在前面取得信用会饿死到期扫描，新增真实循环回归复现四次分页全为 pending。
修复后按原20个固定 Range 份额分别轮转两类可用机会，不预扣/退款，不按循环奇偶
翻转优先级。原生 owner 是唯一扣费方；原有限 Watch 协议保持原样。

自动保留预算 `256*8192+80*4096+32*4096+1MiB+64KiB=3670016 <4MiB`，包含一页
hint 与单个出生/释放证据同时存在。自动模式为这些369个发现身份从原动态缓存预留
4MiB/369项，到期缓存限36MiB/9631项，原总64MiB/10000身份预算不扩大。这是所持对象
计费，不是进程 RSS 或 etcd Count/大N扫描CPU的容量证明。状态快照有界且无权限语义。

所有阶段原始调用返回后才能续租或进入下一个阶段；关闭仍先封锁并等待原注册任务，
再释放会话。没有为每个已有 Task 建 goroutine、额外 session、诊断权限或结果缓存。

## Registry 控制定向回归

新增三项控制回归：32槽满时保留80条页及续页并让出回填机会；最后一槽为重复任务时
仍消费当前 hint；释放一个控制槽后重新选择原候选并进入出生鉴权。测试使用有效不可变
Task 引用，但槽内没有物理任务、Kernel 或运行中的清理链，不作为32并发执行验收。
host 与 race 均通过三项，无跳过或数据竞争；分别9061/9066份输入，源码、工具与归档
前后核对通过。host 日志 SHA256

## 压缩及 session 更换控制回归

新增四个分支验证 actor 组合：pending 页压缩后清除视图/游标并保留至少30秒冷却；
同一压缩伴随原 guard 丢失时失败；legacy 压缩后刷新视图且保留已提交的 cutoff/frontier；
实际释放旧 session 并取得新 session/partition/份额后，从持久 B 续接剩余历史，拒绝旧
游标且不发RPC。这里的持久提交和会话来自现有gRPC元数据模型，不是实际etcd故障或
物理清理验收。host/race 四分支均通过，分别9062/9067份输入，完整输入审计通过；
