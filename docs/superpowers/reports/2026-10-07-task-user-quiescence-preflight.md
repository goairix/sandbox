## Important — amend before dispatch

### I1. Define and own the original namespace/proc/cgroup seal before user admission

**Evidence:** design:86,132 requires the *original* kernel/process/contract seal before/after the terminal scan; plan:41–48 proposes new observation files but omits the original capture point. Existing `internal/runtime/launcher/kernel_types.go:36–42` contains only mutex/self/role/PID/privilege snapshot; `kernel_linux.go:43` constructs that state and `:69` refreshes it. Existing monitor cgroup inspection validates a monitor's current view; it does not give KernelBoundary an original PID1 namespace/proc/cgroup baseline.

**Risk:** an author could compare two final-time snapshots and label them the original boundary, or discover late that required bootstrap changes are outside assigned files. Final-time consistency alone does not certify continuity with the namespace in which original executions were admitted.

**Minimum resolution:** adopt Root's proposed immutable PID-namespace, proc mount/root and cgroup seal during BootstrapPID1 after privilege mutation and before any admitted execution; explicitly add narrowly owned kernel_types.go/kernel_linux.go and fixed seal helper changes to Task2. Specify which identity components are pinned and compared, fail closed when capture/validation is unavailable, retain process-local origin, use only bounded scan-owned FDs with deterministic closure, and expose no raw FD or new privilege. The proposed early capture and ownership expansion resolve the design gap without a kernel redesign. Actual Linux feasibility remains CV1/CV2.

**Required changed-seam evidence:** capture occurs before admission; later namespace/proc-view/cgroup mismatch fails with zero observation; unsupported topology fails closed; successful census revalidates the original seal rather than overwriting its baseline.

### I2. Make registration retirement and owner completion one defined linearization

**Evidence:** design:7,60–68,130,133 and plan:46 require a complete owned execution set, max64. Existing `internal/runtime/controlrunner/supervisor_exec.go:379–381` deletes/publishes active before its outer defer at:221–227 joins watchdogDone and closes ownerDone. A barrier freezing only active can therefore omit an original owner still finishing. MaxActive bounds registry occupancy, not all executions ever run in this runtime.

**Risk:** the new coordinator can falsely claim all original owners joined, omit a finishing owner from its evidence digest, or grow an unnecessary lifetime-history/retiring map to satisfy an ambiguous “all previously registered” requirement. Fresh namespace absence proves process absence, not Go callback/resource ownership completion.

**Minimum resolution:** adopt Root's proposal: retain every registration until original watchdog/callback/pipe ownership has joined, then close ownerDone and remove/publish the entry in the same s.mu-protected retirement transition. Define the frozen set as registrations **not yet owner-joined at the USERS barrier**, excluding already fully joined historical executions. Keep registry occupancy charged against MaxActive<=64 until retirement; no unbounded retiring map or lifetime historical count. Preserve sole Wait and all original failure/start owners. The coordinator must release s.mu before awaiting captured owners, so retirement can acquire it.

The same documented rule must cover pre-spawn failure and normal terminal paths, not only moving the successful tail. Root's proposed direction resolves the gap in principle and remains a next-unit changed-seam requirement, not reopening predecessor acceptance.

**Required changed-seam evidence:** pause a terminal owner after its result/Wait but before watchdog/owner join, cross USERS closure and show it remains captured/charged; release it and verify one retirement. Also force before-spawn, in-flight Start and failure retirement, verify no duplicate channel close/Wait, and admit many sequential completed executions to demonstrate the digest does not mean lifetime history.

## Independently assessed selected decisions

- **D1 accepted as the intended contract, with implementation proof pending.** Section9 moves t0 before pending IO and arms the independent absolute deadline before blocking work, fixes a single31s aggregate budget and <=1s stop-delivery opportunity, makes loss atomic, and joins successful callback ownership. This correctly avoids copying current `supervisor_failure.go:24–25,94–110` as a fresh extra budget. Existing failureOnce/timer behavior must be changed so a newly earlier deadline can shorten an already running isolation owner; sync.Once must not freeze a later deadline. Timer.Stop alone is not callback join. Shutdown must suppress new signing, join the original coordinator and borrowers, and only then destroy journal/key. An expired pending attempt stays closed/unknown; isolation exit70 is not successful join proof. These are required implementation assertions, not defects in the selected section9 contract.
- **D2 arithmetic and primitive are sound.** 32 permanent +8 original claim/guard +3 issuer +1 new-intent absence +4 exact CloseData-intent +1 strictly positive original receipt MOD =49 business comparisons; +1 write +14 unchanged reserve =64 charged. Existing native CommitStage adds8 comparisons, yielding57 comparisons +2 success writes +4 Else reads =63 literal nodes. `mutation.go:115–139` supports/copies MOD, and stage.go:85–109 validates the mutation before Grant. Positive exact revision plus strict observed immutable common-birth/Lease0 state is sufficient to detect later receipt mutation within the pinned cluster/restore domain; do not substitute a revision from another authority or permit zero. Required real mutation and65-charge zero-Grant cases remain necessary. No retention-only63 variant, link transaction or new transaction framework is needed.
- **Final read-only conjunction is adequately bounded.** Section9:134's32+8+4+4+4=52 comparisons and two bounded Range operations total54 nodes. The final full-prefix current limit1 empty observation is distinct from pagination; every response and current claim check must succeed. Pages use current revisions and bounded owned buffers, not a snapshot cursor that claims atomic emptiness. No token deletion, native revoke or recovered OperationCapability is authorized.
- **Authority APIs are coherent after supersession.** PrepareTaskQuiescence and PrepareAfterDualDrain take Destination and obtain/verify exact prerequisite receipts internally under independently configured backend roots, current certificate and bracketing claim checks. A caller's bare proof/boolean cannot replace this process. Diagnostic history cannot recreate effect authority. New-claim historical reconciliation produces only a fresh current-claim local next-phase prerequisite. Equal claim revisions require matching claim/worker/Lease; UUID ordering is irrelevant.
- **Canonical proof contract is sufficiently specific for Task1.** Exact ordered JSON array/fields, original ExecStartContext, sorted unique command UUIDs, literal[] empty hash, original ticket digest and verified terminal receipt digest distinguish never_spawned from local_terminal. The digest is a summary of the bounded live-owner set defined by I2, not a substituted proof of ownership. Current tuple may differ in command/current claimant, while permanent task/birth/runtime identity remains exact.
- **Task1/Task2 trusted producer separation is appropriate.** Task1 may implement pending/barrier/accepted-only behavior; it must not certify registration merely because a standalone journal test calls a signer. Actual accepted ACK requires Task2 supervisor lifetime registration before it can leave the transport. Task2's pre-dispatch concrete interface must keep ownerDone/waitDone validation inside trusted supervisor code and independently validate journal attribution plus fresh opaque kernel observation. Whichever transition wins owns the outcome: stop prevents future cmd.Start, or quiescence awaits the same already committed Start. No new waiter/monitor may substitute for the original owner. I2 adds the necessary retirement half of that ownership model.
- **Namespace proof is plausible but requires the new seal and native evidence.** A complete bounded proc census plus non-reaping Waitid(WEXITED|WNOHANG|WNOWAIT|__WALL) ECHILD after original waits is materially stronger than reusing monitor Drain/Wait4, UID exemptions or a zero WNOHANG result. It must reject ambiguity/overflow/unknown processes. The allowed topology and separate mounter are essential assumptions; this preflight does not certify actual seccomp/kernel support.
- **Combined chain stays an in-unit gate.** Task5 correctly requires real metadata/public backend and actual protected PID1, including delayed old work after native token expiry and both false conjunctions. The concrete same-quota transport topology/custody must be published before launch. No fake target or new child introduced merely to carry fixture traffic may evade the terminal census. Separate passing components are insufficient. Deferring exact fixture wiring until the APIs exist is reasonable and need not block Task1 after I1/I2 are documented.
