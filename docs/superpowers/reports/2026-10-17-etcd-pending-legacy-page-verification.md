# Pending 历史 intent 分页切片验证

本片提供平坦 cleanup-intents 家族的私有固定视图读取，供后续历史回填使用。
它不写检查点、不推进 frontier、不标记回填完成，也不认证 Task 或删除 pending。
默认入口仍使用 Redis，自动消费者、历史覆盖和大N性能尚未验收。

## 实现边界

读取视图来自此前实际读取/提交的检查点；游标同时绑定原 Backend、分区、Range份额、
检查点对象与精确值/修订、截止点、视图和frontier，沿用原DueCursor的一次消费规则。
状态或游标的副本、其他份额、刷新后的检查点均不能采用旧游标。请求仍使用原20个
worker比较、1个Range和4个失败读取，共25节点；检查点是后续CAS的精确前件，
本次Range没有比较检查点，不能将返回页当作当前覆盖区间的权限。

旧通用Stage允许单条64KiB，因此兼容读取限2条、KeysOnly、KEY/NONE、无revision
过滤器。服务端额外一条lookahead计入预算：4096+3×(1024+65536+128)=204160字节。
返回两条空值KV的保守模型为6400字节；这是源码和协议上限推导，未测量真实etcd的
内存或Count计算成本。读取仍完整支付原256KiB Range份额，错误和短页均不退款。

返回行必须为严格有序、范围内的规范UUID键，永久不可变，Version1、Lease0，
Create=Mod且不超过固定视图。值泄漏、后代键、错误计数/修订/头或坏行使整页拒绝。
截止点前后两类行均返回，留给后续算法本地判定；响应字节不会被返回对象借用。

EOF只表明该视图下没有更多行；非空末页中的旧任务仍须认证和持久处理，不能据此
标记完成。后续最小完成路径要在最新持久frontier后取得空EOF，再精确CAS同一检查点。
已知压缩只有在原付费调用中重新认证guards后才保留会话；视图更新仍由检查点协议负责。
原RPC、验证和Relist实际返回前不能释放owner，Close必须等待实际返回。

保留失败；第二轮只缺待实现的私有API，均未执行行为断言。

- host两组/34子例通过1.480s，race同两组/34子例通过2.823s，无跳过、告警或竞争。
- Linux arm64/CGO0的etcd包vet通过，无输出。
- 覆盖0/1/2/3行、持久frontier起点、截止点两侧、固定视图插入/删除、返回字节归属、
  最大通用值、规范UUID/不可变MVCC/范围/计数/响应头拒绝，以及原预算、复制/跨份额/
  刷新后游标拒绝、已知compaction的实际guard检查及Relist/Close实际返回屏障。
