# 清理执行器完整请求预检验证

本片补齐清理消费者在 Claim Grant 前所需的旧链请求预检生产者，继续当前清理执行器 Task。实际消费者、actor mailbox、run/join/终态结算、正向 managed Grant、部署接线及新 Linux 物理组合尚未完成；这不是生产迁移、性能或容量验收。

## 实现与边界

- 固定22类操作，逐一构造142个实际事务形状和5个具体 Lease 请求/响应对。恢复别名明确复用完整 protobuf，不表示额外 RPC；闭合清单拒绝缺失、重复、任意后缀和空事务占位。
- 复用原 Stage、Claim、归档、同步、提供者和安全释放的纯构造逻辑；原现场权限检查、原生调用和调用后检查继续由原对象持有。仅真实 KernelBoundary 可以绑定私有一次性 inventory；元数据 fixture 不能产生执行权限。
- 新消费者逐个测量请求128 KiB、成功/失败响应各256 KiB，字面累计两分支且最多64节点。原通用 Stage 的14节点开销、256 KiB限制及原效果 fences 不变；完整释放事务保持60比较加4写。
- 未来记录先经过原 codec，再以整条记录上限构造 wire；包括七个提供者槽、JSON转义和描述符 base64。关闭、排空、归档、checkpoint 及提供者的记录上限未放宽。
- 修复公共 Stage 可写新永久槽和 execution 行的缺口，保护私有 CAS 历史；邻近业务前缀和 checkpoint 仍可写。

## 失败记录与限制

初始 wire-red-01 仅因新API缺失而编译失败，不计行为证明。随后实际行为测试复现公共 Stage 接受 execution put，以及新构造器共用归档/排空 command ID 导致原 lineage codec 拒绝；均在独立输入核对后窄修。提供者新测试起初误把最大字段组合当作整条记录可编码，改为上述实际字节和正反断言，产品 codec 未改。

首次47组回归 wire-host-01 执行到45组/187子用例后，旧 finalizer 边界测试因新 wrapper 提前读取空 Binding 而 panic。恢复原 binding 非空时才读取 TargetDigest 的条件，旧测试保持不变；其后的完整 host/race 均通过。所有失败原始日志、输入和归档保留，修复前完成逐项核对。

最终 host/race 各10条客户端 warn：8条故意撤销后的 LeaseNotFound、2条取消 Txn。服务器完整日志分别49/42/41条warn、各4条error，包含测试环境共端口/token、lease-not-found、启动peer查找和停止期间的断连；成员0停止时失去quorum并出现leader-transfer超时。12条error均为SIGTERM期间http/mux/listener关闭。没有将这些日志表述为无告警或生产可用性证明。

按 AGENTS.md 检查：清单/准入、Stage、同步、运行时和记录校验分文件，相关共享构造仍留在拥有事务不变量的etcd包；没有为了拆包导出内部权限。完整 inventory 应只在后续准入/Claim窗口保留，不能按全部存活 sandbox 常驻缓存。本片没有真实清理执行、完整Task审查、33个真实Task争抢或大量存量沙盒容量结果。
