## Minor

**M1 — Distinguish the first terminal completion deadline from later successful-history signing.** Draft:76,96,120 permits a terminal history signer after a successful original coordinator, but “No success if remaining time is exhausted at any fixed-purpose signing return” could be copied into that query path and impose the original31s deadline on all future historical queries. It also leaves the failure-to-history transition implicit.

Minimum clarification in the filled brief, without new API or framework:

- Pending admission, initial terminal completion/signing and the atomic coordinator success decision remain bounded by original t0+31s. An expired/failed coordinator can never become successful merely because terminal bytes are readable or a later census is empty.
- Once the original coordinator has successfully completed and joined its deadline owner, later historical signing uses a fresh bounded query context, fresh original-bound namespace observation and currently valid runtime certificate. It does not reuse an expired coordinator context or create a new cleanup deadline.
- Terminal write/rename/fsync uncertainty leaves poisoned/accounting-unknown history unable to sign. A late authentication/context/observation failure returns nil wire and keeps the original coordinator unknown; the Supervisor cannot infer successful completion from the retained state string.
- Lost response **after** successful original completion can be reconciled through authenticated historical query; cancellation of the request borrow alone must not erase a successfully owned completion.

This is a wording clarification to implement the existing successful-coordinator and historical-query contract, not a new authority path or an identified unsafe implementation. A focused test should query beyond the original31s after genuine successful completion, and contrast that with retained terminal bytes from a failed completion that remain unsignable.

## Interface assessment

1. **CompleteUserQuiescence is purpose-specific, not an arbitrary terminal setter.** Draft:57–82 accepts original accepted quiescence/exec handles and an opaque kernel observation; it does not accept caller-written terminal records, digest/count summaries or a generic callback. Journal derives canonical entries/counts from protected original records, validates every handle/origin/context and original receipt, and holds its mutex through revalidation, persistence, signature and postchecks. An exported DTO is expressly a trusted producer input, not proof that Go caller visibility authenticates joins.
2. **Completeness and never_spawned are assigned to the correct owner.** Draft:74–82 gives Supervisor responsibility for its private frozen original registrations and original start decision. ConsumedStart is not misused as proof of actual spawn. The Journal verifies each submitted original handle and record, including terminal result fields and exact verified receipt bytes, but does not pretend to discover omitted registrations without a historical scan. Omission rejection belongs at the Supervisor producer boundary; duplicate/foreign/malformed entries also reject inside Journal. This division is acceptable within the trusted management-process boundary.
3. **The physical observation cannot be refreshed from a timestamp or caller flag.** Draft:38–50,128–132 binds the private observation to the one original process-local PID1 KernelBoundary and immutable bootstrap seal. RevalidateCurrent performs a new complete bounded census and non-reaping ECHILD, with original boundary checks; nil/zero/copy/cross-process inputs reject and no descriptor escapes. Fresh pre-persistence and post-sign observation checks reject stale absence. Journal's own installed identity/key checks and trusted Supervisor selection of its immutable KernelBoundary provide the application/kernel coupling without adding a redundant generic authority object.
4. **Successful historical signing has an explicit producer prerequisite.** Draft:76 requires the original successful coordinator and permanent USERS closure before Supervisor invokes SignUserQuiescenceReceipt. Clean live Journal and fresh physical observation are necessary but do not reconstruct that coordinator from disk. Poisoned/cold/reopened history cannot sign. M1 makes the original-success versus failed-history distinction explicit at the deadline/query boundary.
5. **Registration retirement is bounded and includes the previously omitted tail.** Draft:100–112 keeps registrations charged until original watchdog/callback/pipe/sole-Wait owners finish; ownerDone close and map removal publish under the same s.mu transition used by the barrier snapshot. Captured pointers remain privately owned after retirement, historical fully joined entries are excluded, and no unbounded retiring map/lifetime counter appears. Normal terminal, stop-before-start, in-flight Start and failure paths have distinct completion ownership; no synthetic PID0 terminal or competing Wait is allowed.
6. **The no-Wait path is explicitly different from successful cmd.Wait.** Draft:106–110 closes waitDone only as original no-Wait-created completion after the start owner has cleaned up. It cannot close a live sole Wait worker's channel. A Start already committed but returning error remains conservatively unknown, so an ambiguous partial-start failure cannot become never_spawned.
7. **D1 removes the failureOnce timing hazard without a detached per-execution framework.** Draft:116–124 registers the minimum absolute deadline outside failureOnce, uses one finite timer owner independent of blocking owner/journal locks, and provides expiry-versus-success arbitration plus an actual done join. A later earlier deadline can shorten existing isolation. The one-second fanout budget is aggregate and uses original control owners/TryLock, not64 fresh seconds or unjoined worker goroutines. Future implementation must stop/join the timer owner rather than treating Timer.Stop as callback completion.
8. **Shutdown preserves existing resource ownership.** Draft:94–96,124 separates request cancellation from accepted irreversible cleanup; Close seals borrows/signing and joins this same task/deadline owner and the original execution/transport owners before journal/key destruction. A join timeout cannot report successful teardown. The existing standalone Close policy is retained only when no quiescence attempt exists and cannot extend an already registered earlier isolation deadline.
9. **Original seal and syscall contract are correctly scoped.** Draft:128–132 captures before admitting users, distinguishes the fixed namespace magic-link opening from nofollow ordinary proc files, rejects ambiguous mount/cgroup identity, and closes scan-owned descriptors. The PID1 method observes; it neither invokes monitor Drain nor reaps statuses owned by cmd.Wait. Unsupported or ambiguous platforms return no proof. Actual syscall compatibility is still a mandatory native gate.
10. **Dependency direction and task extraction are narrow.** Draft:138–150 adds controltarget→launcher for the opaque observation, with no reverse import, and keeps terminal implementation in Task2. Task1 contributes accepted pending handles/records and pure terminal protocol; its final actual digest types, getters, original receipt validation and peak IO helpers must be reconciled before coding. No approval of guessed replacement schemas or changes to old canonical exec formats is given.
