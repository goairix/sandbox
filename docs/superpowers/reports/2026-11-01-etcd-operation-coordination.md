# etcd 请求协调优化验收记录

日期：2026-11-01。设计与实现计划已获确认。功能基线为 `7cad09a5`，按任务提交 `b64e504d`、`36197efb`、`e5ac1ce2`、`8bc88d71`、`1a3fe840`；本报告同一提交包含最终故障测试及续期 RPC 期限修正。镜像未构建发布，生产未部署。

## 结果与适用范围

本地协调实现与三成员 etcd 故障测试通过，普通热请求达到一次只读事务、零每请求 KV 写事务，后台维护成本按组摊销。默认 `sharedDataOperations: false`。生产灰度条件尚未全部满足：本轮远端 runtime/helper 使用受控测试实现，尚未完成真实 Kubernetes exec 断连、节点分区下旧 helper 副作用隔离验证。不能把本地取消或租约到期视为这项证明。

## 环境与复现

- Go 1.25.0 项目，client/v3 v3.6.14；客户端 Apple M5 / darwin arm64，Docker 本地专用网络。
- etcd 固定镜像 `quay.io/coreos/etcd:v3.6.14`，3 成员，每成员 1 CPU / 512MiB，回环地址映射 client 端口，周期压缩 1m。测试脚本只清理自己创建的容器和网络。
- 性能：每个正式样本 10000 次请求，64 个 worker（并发上限），最大提供速率 160 req/s；每样本约 62.5s，均不少于 60s，500ms 持有场景受 64 并发限制，实际约 79–81s。8 个样本共约 557s。
- 数据：热点 1 个沙盒；轮换场景 2048 个沙盒，每个约访问 5 次，体现低复用和 1024 组上限回退，并非每个请求都是全新沙盒；双副本共享同一仓库和运行时身份。
- 受控 runtime 仍执行 Manager 的身份检查，但不会产生 Kubernetes GET 或 HTTP/exec 网络耗时；延迟仅用于本地协调对照，不是业务 API SLA，也不是生产最大容量。

```bash
bash scripts/test-etcd-operation-coordination.sh safety
bash scripts/test-etcd-operation-coordination.sh bench
go test ./...
go vet ./...
go test -tags helmtests ./internal/helmtest
bash scripts/test-helm-chart.sh
```

独立 etcd 地址由脚本设置 `TEST_ETCD_ENDPOINT` / `TEST_ETCD_ENDPOINTS`。新集成测试在缺少地址时会跳过；safety 脚本拒绝非预期 SKIP。`TestSharedDataEtcdCrashProcessChild` 是父进程中明确跳过、由进程强杀用例实际启动的子进程 helper。

## 正式固定速率对照

| 场景 | 路径 | RPC/请求 | KV 写事务/请求 | p50 ms | p95 ms | p99 ms |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 单热点 | 原路径 | 6.000 | 2.000 | 3.518 | 23.560 | 59.070 |
| 单热点 | 共享 | 1.001 | 0.000 | 0.930 | 9.161 | 24.800 |
| 2048 沙盒轮换 | 原路径 | 6.000 | 2.000 | 3.549 | 15.820 | 42.980 |
| 2048 沙盒轮换 | 共享 | 5.166 | 1.078 | 3.314 | 13.690 | 47.090 |
| 500ms 持有操作 | 原路径 | 6.000 | 2.000 | 508.400 | 532.600 | 570.100 |
| 500ms 持有操作 | 共享 | 1.002 | 0.000 | 502.600 | 507.900 | 515.200 |
| 双副本热点 | 原路径 | 6.000 | 2.000 | 3.419 | 16.290 | 42.650 |
| 双副本热点 | 共享 | 1.002 | 0.000 | 0.824 | 4.387 | 12.550 |

请求耗时从准入到释放，包含 500ms 持有操作。Go benchmark 的 ns/op 包含限速等待，不代表单请求延迟；表中使用每次调用单独采样的百分位。

热场景已先建立使用组，首建和最终清理不计入稳态窗口。轮换场景包含首建与容量回退：5120 次共享读取、4880 次原路径请求，结束时有 1024 个组；因此收益小于热点，p99 从 42.98ms 到 47.09ms，未改善。不能据此承诺所有文件接口都更快；只访问一次的沙盒还可能承担更多注册/空闲维护成本。

原路径每请求 1 次 Grant、2 次写事务。共享热点窗口 Grant 为 0，组外首建仍需 BeginOperation 的 3 次 RPC、一次绑定确认，再为请求读取一次。共享单热点后台约 6 次 KeepAlive/分钟，双副本约 13 次；计数窗口可能跨过一个维护 RPC，原始数据保留边界差异。

共享轮换样本每请求 Grant 0.5904、KeepAlive 0.6582；Watch 接收 10784 个事件，protobuf Event 载荷约 3.12MB，包含被过滤的子 key 流量。这说明 Watch 和租约维护仍有成本，不能用“请求零写入”概括整个集群。

[机器可读测量记录](2026-11-01-etcd-operation-coordination-measurements.json) 保留逐阶段 RPC、Grant/KeepAlive、延迟、Watch、组/key/集群 Lease 数与 DB 采样。DB 为同一集群连续采样且自动压缩，DbSizeInUse 负增量可能回收上一个样本的历史数据，不代表本功能单独缩小了数据库；集群 Lease 结束数也可能含先前样本尚未到期的空 Lease，不用来推算单场景峰值。

## 安全与恢复验证

| 验证 | 观察结果 |
| --- | --- |
| 新旧三实例混跑销毁 | 关闭新准入后拒绝后续请求，最后共享引用退出前不删除 runtime，退出后完成一次清理 |
| 多组工作区独占 | 等待其他组退出；只剩当前 exclusive 时继续原 fencing |
| 持久 ExpiresAt 过时 | 服务端 Lease 仍活时可读，旧计数/EndOperation 仍有效 |
| 不存在的沙盒 | 新旧路径保持相同的 NotFound 分类，保留 API 404 语义 |
| Lease 撤销、后继 token | 请求 context 取消；旧 token 结束不能删除后继 |
| 真实 API 子进程 SIGKILL | Data 参与者租约过期，持久 sandbox record 仍保留 |
| Watch 读/订阅竞态、压缩、历史溢出 | 通知或 Reset 后权威读回；controller-only 更新不触发生命周期唤醒 |
| 三成员故障 | 停一个成员后仍能准入；再停一个、失去 quorum 后请求失败，不使用缓存授权；恢复成员后完成清理 |
| 取消、长流、shutdown | 单请求取消不取消同组请求；远端 join 前引用保持，Stop 超时不提前 End |
| 迟到/阻塞续期 | 不从收包时间延长 TTL；RPC 期限受上一次确认的本地保护期限约束 |
| 1024 组容量回退 | 同时持有 2048 沙盒，1024 个共享组，2048 个 leased operation / 不同活 Lease，命名空间共 8192 个 key；保护未因回退丢失 |

三成员最终 safety 运行通过，sandbox 包约 27.343s。容量单独运行也通过，约 7.15s；上述容量数是在所有 2048 引用同时持有时的可观测高水位，不是生产上限。

负向对照均验证了测试有效性，随后恢复源码：把流 release 移到 reader.Close 前，join 测试因引用从 1 提前变为 0 失败；绕过排空权威判断，混跑销毁测试观察到 runtime 被提前删除而失败。新增阻塞续期测试先观察到“超过确认期限仍未结束”的失败，再将维护 RPC 绑定至原确认期限后通过。

主仓库 `go test ./...`、`go vet ./...`、配置/入口/指标测试、Helm 渲染测试和脚本通过。普通不配置后端的测试运行会跳过需要外部 etcd/Redis/集群的既有测试；真实 etcd 的本次协调验收由独立 safety 脚本覆盖，不能把普通全套绿色当作全部远端测试已运行。

## 独立审查与修正

独立审查提出 1 项 Important：client/v3 v3.6.14 的 Watch 内部响应缓冲无上限，本地 history/订阅队列有界并不能约束入口。已验证依赖源码，并用真实 gRPC 慢消费者回归复现：停止消费通知后，旧实现仍在约 0.05s 内接收完整 64MiB 洪流。

修正为在已有 client 连接（保留连接的 TLS/认证设置）上使用生成的 Watch RPC，按需 Recv，利用 HTTP/2 流控提供背压；单响应限制 4MiB、4096 个事件，不通过 clientv3.Watch 的隐藏队列。超出预算、意外 fragment 或压缩/断线均取消旧流并发 Reset，按 revision 恢复或重新读取，最终权威确认不变。预算是单响应/事件上限，不能解释成进程总内存只有 4MiB。

慢消费者、4097 事件响应和 5MiB 消息三个回归均先失败，再通过。修正后全套检查与三成员故障验收重新执行；未启动第二轮独立审查。本报告原始八组性能数据记录的是此入口修正前的 `e2c13066`，修正后的共享路径复核另行保存，不把原有延迟直接当作修正后的 SLA。

修正后在相同三成员规格、160 req/s 和 10000 请求下复测两个受影响场景（约 136s，含准备）。热点协调仍约一次读取，轮换场景仍含组维护和容量回退；下表与 JSON 的 `post_review_results` 对应，其他原始样本保留为历史测量。

| 场景 | RPC/请求 | KV 写事务/请求 | p50 ms | p95 ms | p99 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 热点共享 | 1.001 | 0.000 | 0.860 | 1.327 | 2.321 |
| 2048 轮换共享 | 5.175 | 1.078 | 3.197 | 26.960 | 351.200 |

修正后的轮换样本 p99 达到 351.2ms，高于先前共享样本 47.09ms 和原路径 42.98ms。这是本轮不默认开启的实际限制：低复用首建、组维护、存储与调度压力可能恶化尾延迟，需在目标工作负载中验证，不能只看 RPC 总量。两轮使用相同规格的新测试集群，但前置数据库历史不同，本机调度和后台负载也会影响尾延迟，因此不据此把变化全部归因于 Watch 入口修正。修正后的三成员 safety 再次通过（sandbox 包约 32.964s），全套 `go test ./...` 与 `go vet ./...` 通过；三个传输级回归均 RED→GREEN。原有 etcd API 与 gRPC 模块只从 indirect 标记提升为直接依赖，版本未变，无新增模块。

## 后台成本与范围

业务 Data 读取、组注册/释放、组 renew/KeepAlive、排空 Observe 和 Watch 分别打点。现有 `sandbox.controller.stage.duration` 独立保留。受控 benchmark 没有启动 FUSE 工作区控制器或业务生命周期扫描，因此不声称降低所有后台成本。

既有真实 etcd `TestControllerStagesObserveAcquireAndRenew` 本轮复核通过：同 TTL 控制器一次 renew 正常路径为只读事务、CAS 写事务、KeepAlive 共 3 次 RPC。按 5s 周期换算是每控制器约 0.6 RPC/s，仅是路径估算，实际还受 fencing、扫描和健康检查影响。workspace owner、pool 和控制器协议本轮没有重构。

## 保留的失败试验

首次 64-worker 不限速、自动校准 60s 的试验中，1 CPU/成员的集群持续接近 CPU 配额，原路径出现 3 秒超时。内存约 144–157MiB/成员，容器未 OOM；取到的 10000 请求校准样本仍是 6 RPC/请求，但后续饱和运行失败，不能作为成功吞吐或容量报告。

终止该专用测试后，改为相同 160 req/s 提供速率、64-worker 上限、固定 10000 请求，使每条路径运行约 62.5s（不少于 60s）。保持资源限制，未通过提高配额掩盖失败。该选择用于比较健康路径成本，未测绝对饱和点。

## 灰度与回退

按 [生产部署文档](../../deployment/helm-production.md#共享-data-operation-协调优化) 构建新的明确 API tag，并在独立环境补齐 Kubernetes 远端隔离验证。然后用单实例灰度 API、相同 state scope 和已有 etcd，对比新旧混跑；开关默认关闭。

关闭灰度时先停新准入，等待 helper Close/join 后正常退出，再关闭开关或回滚镜像。不删 owner/operation key、不清 PVC、不在 etcd 不可用时自动改用 Redis。若远端隔离无法证明，保持开关关闭并单独处理，不将本报告当作生产开启批准。

## 执行取舍

- 使用原提交创建托管工作区，隔离原分支；代价是后续需整合该功能分支。
- 安装的技能脚本没有可执行位，使用 bash/等价本地 brief 与 ledger，不修改已安装技能；代价是手工维护执行记录。
- 共享组维护上下文与控制器取消分开，通过显式 Stop/join 收尾；代价是未释放的 helper 会继续保留保护，不能用超时强删。
- API 模板快照 hash 随默认 false 环境变量更新；新增语义测试核对 StatefulSet 与 backend identity 不变，避免只依赖快照；仍需警惕未来 hash 更新掩盖无关变化。
- 不为 main 中单一 bool 赋值添加镜像式测试；通过配置加载、Manager 行为、Helm 渲染及入口构建覆盖，代价是未来误删接线可能需要集成测试发现。
- 固定速率替代饱和自动校准，保留失败记录；代价是本轮没有给出最大容量或所有负载下的延迟保证。

- 最终审查对真实 Kubernetes 旧 helper 隔离的判断：保持未验证且阻止生产开启，代价是无法保证故障时旧副作用已被隔离。
- 最终审查对容量/端到端延迟的判断：仅报告固定速率协调测量，代价是不提供生产最大吞吐或 HTTP SLA。
- 为约束内存改用已有连接上的直接 Watch RPC；代价是自行维护 revision 恢复、压缩和进度处理，已用真实 etcd 和传输级回归覆盖。
